Staged relaxation workflow — how to tighten convergence without losing previous work

SIESTA writes three "state" files into the run directory at every run with the same SystemLabel. Re-running SIESTA in the same directory with the same label automatically picks them up and continues — that's the mechanism for incrementally tightening convergence parameters without re-doing the early relaxation steps.

Surprise: SIESTA silently overrides the AtomicCoordinatesAndAtomicSpecies block in the FDF whenever a <label>.XV file is present in the run directory. The saved coordinates win, not the FDF's. Same for <label>.DM (density-matrix warm-start) and <label>.CG (CG state). This is what makes the recipe below work — stage 2's FDF can carry stage 1's input coords and SIESTA still picks up stage 1's converged geometry. If you want a clean fresh start, either run in an empty directory, delete the .XV / .DM / .CG files first, or change SystemLabel. SIESTA falls back to the FDF coordinates silently when none of those files exist — no warning either way.

Restart files (written automatically)

FileHoldsRead by
<label>.XV latest atomic coordinates + velocities MD.UseSaveXV true
<label>.DM converged density matrix from the last SCF DM.UseSaveDM true
<label>.CG conjugate-gradient line-search state MD.UseSaveCG true (CG only)

molbuilder generates FDF files with all three flags on by default — a continuation works for free as long as you keep the same SystemLabel in the same directory.

The Build tab's Relaxation stage select (in the SIESTA panel) bulk-fills these values. Generate one FDF per stage; run SIESTA on each in turn with the SAME SystemLabel in the SAME directory.

What you can change between stages — and what you can't

✔ Safe to change
  • Convergence parameters (force tol, DM tol, max displ)
  • MeshCutoff (mesh re-built; DM transfers)
  • k-grid (DM transfers; one cold SCF step possible)
  • MD.TypeOfRun (CG → Broyden → FIRE)
  • PAO.EnergyShift, IF orbital count doesn't change
  • DM.MixingWeight / SCF damping
✘ Will break the restart
  • Number of atoms / atomic species
  • Pseudopotentials (different .psml files)
  • Basis size (SZ / DZ / DZP / TZP)
  • Lattice vectors (different cell)
  • SystemLabel (then SIESTA can't find the saved files)
  • Spin polarization toggle (DM shape changes)

Step-by-step

  1. Build tab → Generate FDF with Relaxation stage = Coarse. Save as e.g. job-stage1.fdf in your run directory.
  2. Run SIESTA: siesta < job-stage1.fdf > stage1.log. Open the job.molwatch.log in this Watch tab to monitor convergence.
  3. When stage 1 converges (or stalls near the basin), back to Build tab → switch Relaxation stage to Medium (the form fields update automatically). Generate FDF again, save as job-stage2.fdf in the SAME directory.
  4. Run siesta < job-stage2.fdf > stage2.log. SIESTA reads job.XV and job.DM from stage 1 — the first SCF starts warm, subsequent geometry steps need fewer SCF iterations.
  5. Repeat with Relaxation stage = Tight for the final production geometry. The relaxed coordinates land in job.STRUCT_OUT; you can also use the Save current frame as XYZ button on this Watch tab to grab any frame.
