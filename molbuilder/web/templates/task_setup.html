What came over

Read-only. Set where the calculation was described; change it there, not here — changing these is changing what the calculation is.

How the files are kept apart

Every attempt in one directory, or a directory per attempt. There is no default — it decides where results land, so it is asked, never guessed.

Needed before this can be written

Which machine is this for

A deck carries the machine's numbers — ranks, memory, whether there is a queue — so preparing it needs to know which machine. There is no default when several could be meant: being asked costs one click, being given the wrong one costs a queue wait and an allocation.

Needed before this can be prepared

Where it runs, and what it may use

Pick a queue and these fill with what that queue allows — the most you can ask for there. Lower them if this job needs less; a smaller ask is usually scheduled sooner. Left blank, the scheduler decides, and on many clusters its own default is far below the node.

    Tell me how it is going

    A long run does not need watching. Tick what is worth a message and it is written into this calculation's description. A run ending always reports — that is the whole point, so it is not a choice.

    Send it to

    Channels are named once on the This machine tab; this picks which of them this calculation uses. Only the names travel — no address and no key reaches this page, or the file it writes.

    {#- WHAT IS IN THE MESSAGE. `stages.md` § 6.9. The calculation's name is deliberately NOT a checkbox: it is always sent, because a report you cannot attribute to a job is a notification you have to go and look up. -#}

    What each message says

    Every message names this calculation and its job id — that part is not optional. These pick what else it carries. Anything the monitor could not work out is left out whether or not it is ticked.
