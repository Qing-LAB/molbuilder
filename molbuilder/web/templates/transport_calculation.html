1. The junction

Point the calculation at one directory that already holds a relaxed junction. Every later stage is derived from it: the sorted copy, both electrode cells, the device, the transmission. Nothing is uploaded or copied here — the directory is cited.

A directory qualifies by its files, not its name or location, in one of two shapes:

  • .fdf + .XV — a relaxation that concluded. Its deck answers the basis, functional and mesh, and step 2 shows them as the run's, yours to change.
  • .xyz + .molstruct.json — a labelled structure. A record saved with it answers the same values; without one, step 2 asks for them.

Pick any directory: the line under the button names what it is, or what it is missing. The viewer then shows the cited structure with its region labels — use it to check that the electrodes and the bridge are the atoms you meant.

Labels are assigned where the junction is built, on the Molbuilder tab, never here. The convention is L-electrode at low z and R-electrode at high z: atom order follows the geometry, but the bias µ = +V/2 follows the name, so labelling them the other way round biases the other lead. That case is detected below and offers a rename.

2. Shared by every rung

One electronic description for all five stages. The lead self-energy attaches to a device Hamiltonian built the same way, so the basis, the functional, the mesh, the energy shift, the electronic temperature, the spin, the species order and the transverse k-sampling are decided once, here, and no stage may override them. Changing a value here rebuilds all five stages.

4. The physics, rung by rung

{#- THE BIAS LEADS, because it is the experiment and it GOVERNS the fields under it: at zero bias the whole non-equilibrium half of the density contour is inert, and more than one value turns the run into a chain of attempt ladders. It sat in card 4 beside the Describe button until 2026-09-15, which read as though it were a property of SAVING (`engines/transport.md` 3.4). -#}

The bias is the experiment, so it is asked first — and it decides whether the rest matters. At 0.0 the junction is at equilibrium and every field marked non-equilibrium below does nothing. Several values are a scan: one run per voltage, launched as a single chain job, each starting from the one before it.

Everything below is a knob this calculation actually has, ordered the way you decide them: what is computed (the energy window and its k-sampling), how sharply (broadening), what gets written (outputs), then the machinery (the density contour, the leads) and the shell. The grey tag under each field is the exact fdf keyword it writes, so a setting can be looked up in the SIESTA manual by name; help expands the reasoning and the citation.

Basis, functional, mesh and the rest of the shared description are not here. They bind every rung, so they are set once on step 2; a value given to one rung here would let the device disagree with its own leads, and the describe door refuses it by name.

{#- ===================== 5. Describe ===================== -#}

5. Describe

Write the calculation down. This produces task.json — the citation, the bias list and your per-rung settings from step 4 — and the template that carries the shared description from step 2, in the folder selected in the Projects sidebar. It runs nothing; the stages are prepared and launched afterwards.

Select a folder of its own, not the cited junction: a calculation does not live inside its own input. Make one under this project and select it in the sidebar.

Reference — Transport contract: § 1 one citation → five derived stages, § 3.4 the workflow end to end.

{#- The road after describing — the composite's own quickstart. -#}
What happens after this — the five stages, in order
  1. Prepare and launch each stage from Task setup on that folder, or from the CLI. Each stage gathers what it needs from the stages that finished before it, so the order is not optional: seed → electrode_L → electrode_R → device → transmission.
  2. Why five and not one: tbtrans needs each lead's converged bulk Hamiltonian before it can build that lead's self-energy, and the device needs both. A bias scan is still one job — it walks the voltages, each warm-started from the previous point's density.
  3. Read it back with summarize run, which writes <label>.transport.json: T(E) per bias, the conductance at E_F, and the I–V table from tbtrans's own integral.
