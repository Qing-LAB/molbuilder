Transport calculation

Generates TranSIESTA (NEGF) input scripts for a relaxed device geometry. Pick the relaxed structure in the Projects sidebar (double-click to commit); the form below is populated from TransportConfig via the schema endpoint /api/transport/schema. TranSIESTA zero-bias is shipped 2026-06-10; PySCF-NEGF and several follow-ups (electrode wizard, bias-scan driver, /results inspector) land in subsequent commits — see docs/roadmap.md § 2.2.

Today's runnable workflow (transiesta, zero-bias):

  1. Pick a relaxed device .xyz in the sidebar (double-click to commit). A matching .molstruct.json sidecar must carry the L-electrode / R-electrode / bridge region labels (assign them on the Molbuilder tab).
  2. Configure the form below. Generate enables once the structure is committed.
  3. Click Generate. The rendered .fdf appears inline with Copy + Download.
  4. Generate electrode .TSHS files separately (manual today; "electrode wizard" planned). Build the lead geometry on the Molbuilder tab, emit a SIESTA .fdf from Optimization, add TS.HSFileEnable = T, run SIESTA, copy the resulting .TSHS file into the device run directory as <jobname>_L_electrode.TSHS (and similarly for the right electrode).
  5. Run the device .fdf via the standard bash <jobname>.run.sh wrapper (generated alongside the .fdf; activates the molbuilder-siesta conda env + launches mpirun siesta).

Multi-bias scan: set bias_voltages_v to a list and the preflight will warn that today's engine emits only the first value. Multi-bias requires multiple .fdfs and a driver script — planned as a follow-up.

Where chemistry comes from on Transport. TransportConfig intentionally has no (charge, spin, method) fields — those travel from the upstream relaxed geometry via its .molstruct.json sidecar. Set them once on Optimization or Spectrum calculation (the Auto-detect button on either page surfaces the chemistry rationale before you generate), commit the result, then load the relaxed structure here. Transport's preflight reuses the same shared open-shell-metal check from molbuilder.validation._check_open_shell_metal so a Fe-bearing device surfaces the warn in the issues panel below.
