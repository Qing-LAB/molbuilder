## 1. What this session was for

It started as a review of structure-metadata handling and turned into one
specific question, which the user framed and which then explained a family of
bugs:

> **`cell_origin` is a label on the coordinates beside it. It is not metadata
> that travels on its own.**

A structure can carry an explicit box (`cell`) and a note saying where that box
sits in space (`cell_origin`). That corner is measured against **one particular
set of coordinates**. Move to a different set — say, the coordinates SIESTA
wrote back after a relaxation — and the old corner is meaningless. Anything that
then shifts the atoms by that corner displaces the whole structure.

Three places in the code did exactly that, each written independently, none
aware of the others. A fourth place (`modify.calibrate_to_cell`) had always done
it correctly, and became the reference implementation once the rule was named.

The session's second half came out of the same review: a lattice-spacing formula
that lived in JavaScript, was missing a row, and had no way to be checked.

## 2. What changed, and why it mattered

### 2.1 The origin rule (three defects, one cause)

| where | what it did | what the user saw |
|---|---|---|
| `transport/compose.py`, form A | applied the **authoring** sidecar's `cell_origin` to coordinates read from a `.XV` | the junction was emitted translated by the whole authoring corner; far-face atoms wrapped into the leads |
| `siesta/input.py` (deck writer) | shifted the atoms into SIESTA's frame, then built the validator's copy still carrying the **old** corner | a false *"atoms are outside the box"* warning with a −19 Å clearance, on a junction whose atoms sit perfectly inside |
| `web/blueprints/watch.py` (Results tab) | combined a run's engine-frame coordinates with the **authoring** pair's corner | the box was drawn off the atoms; exporting from that tab carried the bad corner into the next deck, shifting it a second time |

All three now restate the origin in the same breath as the reframing. The rule
is written into `model/structure-periodicity.md` § 6 as clause **2b**.

**One thing the first commit got wrong, and it matters for future work.** That
document used to say `null` = `(0,0,0)`. It does not. `null` means *derive the
corner*: `bbox_min − vacuum` on an isolated axis, `bbox_min` on a transport axis,
`0` on a periodic one — and *no shift at all* only when the box already at the
origin contains every atom. For three isolated axes with 8 Å of vacuum those two
readings are 8–11 Å apart. The corrected rule is clause **2a**. Comments
repeating the old rule were found in two later sweeps and both missed the field
declaration in `structure.py` itself; if you find another, it is wrong.

### 2.2 Reading does not judge (user ruling)

`Structure.__post_init__` used to refuse a zero-volume cell outright. That made a
`.molstruct.json` holding a bad box **impossible to open** — and the Cell page is
the only place a box can be fixed, so the only ways out were to hand-edit the
JSON outside molbuilder or delete it and lose the labels.

Per § 8.2, the box now loads and the load **reports** it. The two doors that act
on a box still refuse: the edit gate (`periodicity_gate`) rejects the value you
type, and the emitter refuses to write a deck. This is deliberate and should not
be "fixed" back.

**The trap it left**, found in self-review and worth knowing about: two guards
elsewhere had been leaning on that constructor refusal without saying so. One
(`transport/compose.py` form B) checked only *"is the cell None?"* where form A
checked the determinant. Both now ask one shared question, `_unusable_cell`.

### 2.3 The seam reports the box, not just the metal

Building a slab onto a molecule captures a cell sized around **every** atom, but
the stacking verdict is measured on the **metal** atoms alone — and has to be,
because the layer detector would read a molecule's atoms as extra layers.

The result was that a junction could report *"the crystal continues across the
periodic boundary, layers 3.400 Å apart"* for a boundary with **0.00 Å of room** —
and the 3.400 Å was the molecule-to-slab standoff, not a layer spacing. Both
facts are now reported. Per the user: **a notice, never a refusal** — the box is
the author's to set, and a collision is legitimate in a relaxation whose outer
layers are frozen.

### 2.4 One rule for the layer spacing

The spacing between atomic layers was computed **in the browser**, as three
literals, and was missing `d(110)` entirely — so building fcc(110) showed you two
spacings, neither of which was the number the Cell page asks you to type.

It is now one rule in `cell.interplanar_spacing`: the cubic formula evaluated at
the **first allowed reflection** for the lattice's centring. fcc allows h,k,l all
the same parity, bcc allows h+k+l even. That is why fcc(100) is `a/2` and not
`a`. A system with no rule (hexagonal) **refuses** rather than returning a
plausible wrong number.

It sits beside `bulk_z_period` and `detect_layers`, which *measure* the same
quantity off atoms — and that adjacency buys a test neither half had: predicted
== measured on a real ASE slab, for all three surfaces.

The browser asks `GET /api/modify/spacings`.

### 2.5 Nothing is implicit (user ruling)

> *"We cannot allow none… It's going to be deceiving. It's going to give the user
> the wrong idea of how this is used."*

Every door returning a spacing **requires** the reference: the word
`experimental`, the word `pbe`, or a number. No default. The two differ ~2% for
gold, which is enough to strain a junction.

Same principle applied to the data file: an override
`$MOLBUILDER_DATA_DIR/fcc_lattice.json` is **honoured or refused, never
half-read**. Before, a trailing comma made it silently return the packaged
4.0782 to someone who had typed 4.20 — and the panel displayed 4.0782 under a
radio labelled "Experimental". *Absence* still falls back; a file that is there
and unreadable does not.

### 2.6 `--electrode` can pick a stacking registry

`junction-cell.md` § 3.1a has recorded since 2026-09-15 that the walk
(`ABC`/`ACB`) does **not** decide the seam — `start_registry` does — and that the
web slab card exposed it while the CLI had no way to say it. The note said to fix
the sentence and the CLI together; only the sentence had been done.

`--electrode Au:111:3x3x3@contact=2.4:registry=B:+z=3`. Accepts `A`/`B`/`C` or an
index; omitting it means registry 0, so **every existing command line is
unchanged**. Measured: the starting layer moves by `a/√6` = 1.665 Å between A and B.

### 2.7 Smaller, same session

- `Structure.to_ase()` handed over atoms alone, so a crystal arrived in ASE as a
  gas-phase cluster (zero cell, `pbc` all false). It now carries the resolved box.
- `concat` took the **whole** non-atom block from whichever input had a cell, so
  appending a slab onto a molecule replaced the user's typed 8 Å vacuum with the
  slab's deliberate zero and turned two isolated axes crystalline — silently. A
  cell and its corner are what a fragment can supply; `axis_kind`, `vacuum` and
  `info` are facts of the canvas.
- Two `dataclasses.replace` calls on a `Structure` were sharing `cell` and the
  `info` dict with their source. `dataclasses.replace` does **not** dispatch to
  `__replace__` on any Python version — it calls `obj.__class__(**changes)` — so
  `Structure.replace` is the only correct door. (A docstring and a test in the
  repo still claim 3.13+ fixes this. They are wrong; see § 4.)
- `replace(pbc=…)` was being silently discarded by the carried `axis_kind`.
- The deck's provenance comment claimed three false things under an explicit cell
  and measured hexagonal `b` 13% short (`np.diag` is the axis length only for an
  orthogonal cell).

## 3. The rule this session added to the playbook

`process/code-audit.md` § 1d gained a **step 0**, and it is the thing to carry
forward:

> **Decide something is obsolete by READING, never by a reference scan.**

A grep, an AST pass or `git log -S` establishes reference facts. A reference fact
cannot tell apart the only two things that matter:

| "no caller" can mean | what it is |
|---|---|
| something better replaced it | **residue** — delete it |
| a caller was **lost**, and the rule it carries silently stopped running | **a regression** — restore the call |

Both look identical to every tool. The bar: read the owning module end to end;
read what replaced it and name the rules it covers; read the history for why the
caller went; read the test that keeps it alive.

**This session broke that rule twice and both are instructive.** Removing the
constructor refusal (§ 2.2) orphaned a guard nobody had noticed was load-bearing.
And a reported crash — *"a form-B citation dies in `axis_vacuum` with a raw
`LinAlgError`"* — was asserted by two independent reviews after probing that
function **in isolation**. Traced end to end, it is false: the validator runs
before any geometry is emitted, so the deck path answers
`[cell.no_volume] This box is flat`. The fix was still right, for a different and
smaller reason (the refusal lands at the citation door, in the citation's words),
but the stated consequence was wrong in a commit message, a docstring and a test
until it was checked.

### X1 — Transport historical residue · **leads, not a deletion plan**

Five candidates found by reference scan plus spot reads. **None has had the
step-0 pass, and none should be deleted until it does.** The user was explicit:

> *"I don't want you to just grep and diff… You need to do a full code review
> before you decide if your decision about a piece of function is correct."*

1. **`transiesta._compute_cell_from_extents`** (+ `_TRANSVERSE_PAD_ANG` and its
   two callers). Fabricates a box — 30 Å transverse padding, `int(bbox_z+2)+1`
   along transport — which is precisely what `Structure.resolve_cell()` forbids
   (*"a periodic axis needs a commensurate lattice … never a bounding box"*). It
   predates `cell.py` entirely (commit `8c70e721`). Believed unreachable because
   compose refuses a cell-less citation on both forms and `as_structure()` always
   states one. **This is the one that looked like a live sanctioned feature
   because a document said so** — see D5.
2. **`wizard.DEFAULT_ELECTRODE_KZ`** — the third home of the number `40`, measured
   equal to the catalogue row and the `SiestaConfig` default.
3. **`stages.SEALED_TRANSPORT_FIELDS`** — a union of two sets that production
   reads **separately**; nothing reads the union.
4. **`stages.config_for`** (~90 lines) — the pre-TR4 projection, superseded by
   `jobset/prep.py::_resolve_transport`. **Read this one carefully**: it is the
   example in § 1d of a thing that looks identical to a lost caller. It was
   settled as residue only by reading the replacement end to end and finding it
   does strictly more.
5. **`TransportConfig.num_threads`** — no reader, hidden from the served form by a
   predicate filter. **Not a defect**: a dead field behind a working guard. The
   live control is `SiestaConfig.omp_threads`.

### X2 — Two `.xyz`/sidecar items · **parked deliberately**

The user is separately revising metadata-on-`.xyz`, and asked that this audit not
collide with it:

> *"I'm working on the metadata associated with XYZ files so I don't want overlap
> between this audit and that effort."*

**Re-verify both after that branch merges** — the second may simply disappear if
the sidecar reader gets unified.

1. **A bare `.xyz` read loses `transport`.** `to_extxyz` writes `pbc="T T T"`;
   `from_xyz` reconstructs `pbc` only, and `axis_kind` is then derived from it —
   but `transport` and `periodic` are both `pbc=True`, so the boolean cannot carry
   the distinction back. **Narrower than it first reads**: the codec writes plain
   `to_xyz()` (no `Lattice=` header) for a single geometry, and through the *pair*
   the sidecar restores `axis_kind`. It bites a frame-range save read back without
   its sidecar. Cost: the k-grid warning for a transport axis cannot fire, so a
   fake Bloch periodicity along transport passes unremarked (invariant I8).
2. **The L/R electrode swap hand-writes the sidecar** (`compose.py`, `json.loads`
   + `json.dumps`) instead of using `molstruct.load`/`dumps`, the one serialisation.
   The escaping difference (`α-helix` vs `α-helix`) is **fidelity, not
   corruption** — an earlier audit overstated this. The real defect is the **read**:
   `molstruct.load` opens `utf-8-sig` and validates the schema, this does neither,
   so a sidecar with a byte-order mark raises `JSONDecodeError` and the route
   catches only `ComposeError` → **HTTP 500**. *Not* a defect: it does not set
   `labels_modified`, which is a 2026-08-29 user ruling, not an oversight.

### X3 — The Cell page commits a box and returns no seam verdict

Verified: `classify_seam` and `_seam_notices` have exactly **one** caller between
them, the slab route. The cell-commit door runs the periodicity gate and never
asks about the seam. So the canonical junction walk — build slab, see
`collision`, set `c` on the Cell page — gets **no answer at the one moment the
geometry is complete**, which is where `junction-cell.md` § 6.1 says the loop
closes.

**A report, never a gate.** The CLI half of this was raised and **dropped on the
user's ruling** — *"people working with CLI would know what they're doing… leave
that out"* — so do not re-propose it.

### D5 — A design document calls live code deleted

`engines/transport.md`'s *"deleted | why"* table lists three things that are
still there and still running (`SEALED_ALWAYS`, `CONTRACT_FIELDS`,
`dataclass_to_form_schema` — the last has a live caller, and a test even records
the contradiction in prose). Two other documents describe a
`transport/_cli.py::_load_device` module and a `--cell-fdf` flag that do not
exist, and a `frame_shift` provenance stamp that nothing writes or reads.

**Why this is not tidiness:** it is what made X1① read as a sanctioned live path
instead of residue. The table must be checked row by row against the code before
anything is trusted from it.

**Also in this class, found late and not yet swept:** `structure.py`'s own
`replace()` docstring and `tests/test_structure_replace_door.py`'s
`TestTheInterpreterHook` both state that Python 3.13+ routes
`dataclasses.replace` through `__replace__`, so "the trap is gone" there. It
does not — the stdlib helper calls `obj.__class__(**changes)` and never consults
`__replace__` on any version; only `copy.replace()` dispatches. The test is
`skipif(>=3.13)`, so **on a 3.13 upgrade it goes quiet while the aliasing it
guards is still live**. Worth folding into D5's sweep.

## 6. Standing constraints worth restating

These are the user's, and they governed everything above.

- **`projects/` is real research data.** Never read, grep, count, parse or cite it
  as evidence. Build a fixture; derive numbers from the writer.
- **A green test proves nothing until the code is broken and the test observed
  failing.** Every fix in this range was mutation-checked. *(One caution: a
  mutation harness with an unquoted `-k` selector will word-split a `'A or B'`
  expression, pytest errors, and the run reads as a false SURVIVED. Quote it.)*
- **Run the full suite before saying done.** 583 targeted tests were green while a
  membership assert that enumerates the whole app was failing — a file-scoped run
  cannot see it.
- **Do not be the user's nanny.** A warning is a warning; the box, the lattice
  constant and the geometry are the author's to set. Bad contacts show up in the
  calculation as bad contacts.
- Tests run under the `molbuilder` env via `tools/testrun.py`. Never pipe it
  through `tail`/`head`. Never `git checkout` to undo an edit — copy to a
  scratchpad first.
