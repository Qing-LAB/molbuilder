## 1. What this session was for

It started as a review of structure-metadata handling and turned into one
specific question, which the user framed and which then explained a family of
bugs:

> **`cell_origin` is a label on the coordinates beside it. It is not metadata
> that travels on its own.**

A structure can carry an explicit box (`cell`) and a note saying where that box
sits in space (`cell_origin`). That corner is measured against **one particular
set of coordinates**. Move to a different set — say, the coordinates SIESTA
wrote back after a relaxation — and the old corner is meaningless. Anything that
then shifts the atoms by that corner displaces the whole structure.

Three places in the code did exactly that, each written independently, none
aware of the others. A fourth place (`modify.calibrate_to_cell`) had always done
it correctly, and became the reference implementation once the rule was named.

The session's second half came out of the same review: a lattice-spacing formula
that lived in JavaScript, was missing a row, and had no way to be checked.

## 2. What changed, and why it mattered

### 2.1 The origin rule (three defects, one cause)

| where | what it did | what the user saw |
|---|---|---|
| `transport/compose.py`, form A | applied the **authoring** sidecar's `cell_origin` to coordinates read from a `.XV` | the junction was emitted translated by the whole authoring corner; far-face atoms wrapped into the leads |
| `siesta/input.py` (deck writer) | shifted the atoms into SIESTA's frame, then built the validator's copy still carrying the **old** corner | a false *"atoms are outside the box"* warning with a −19 Å clearance, on a junction whose atoms sit perfectly inside |
| `web/blueprints/watch.py` (Results tab) | combined a run's engine-frame coordinates with the **authoring** pair's corner | the box was drawn off the atoms; exporting from that tab carried the bad corner into the next deck, shifting it a second time |

All three now restate the origin in the same breath as the reframing. The rule
is written into `model/structure-periodicity.md` § 6 as clause **2b**.

**One thing the first commit got wrong, and it matters for future work.** That
document used to say `null` = `(0,0,0)`. It does not. `null` means *derive the
corner*: `bbox_min − vacuum` on an isolated axis, `bbox_min` on a transport axis,
`0` on a periodic one — and *no shift at all* only when the box already at the
origin contains every atom. For three isolated axes with 8 Å of vacuum those two
readings are 8–11 Å apart. The corrected rule is clause **2a**. Comments
repeating the old rule were found in two later sweeps and both missed the field
declaration in `structure.py` itself; if you find another, it is wrong.

### 2.2 Reading does not judge (user ruling)

`Structure.__post_init__` used to refuse a zero-volume cell outright. That made a
`.molstruct.json` holding a bad box **impossible to open** — and the Cell page is
the only place a box can be fixed, so the only ways out were to hand-edit the
JSON outside molbuilder or delete it and lose the labels.

Per § 8.2, the box now loads and the load **reports** it. The two doors that act
on a box still refuse: the edit gate (`periodicity_gate`) rejects the value you
type, and the emitter refuses to write a deck. This is deliberate and should not
be "fixed" back.

**The trap it left**, found in self-review and worth knowing about: two guards
elsewhere had been leaning on that constructor refusal without saying so. One
(`transport/compose.py` form B) checked only *"is the cell None?"* where form A
checked the determinant. Both now ask one shared question, `_unusable_cell`.

### 2.3 The seam reports the box, not just the metal

Building a slab onto a molecule captures a cell sized around **every** atom, but
the stacking verdict is measured on the **metal** atoms alone — and has to be,
because the layer detector would read a molecule's atoms as extra layers.

The result was that a junction could report *"the crystal continues across the
periodic boundary, layers 3.400 Å apart"* for a boundary with **0.00 Å of room** —
and the 3.400 Å was the molecule-to-slab standoff, not a layer spacing. Both
facts are now reported. Per the user: **a notice, never a refusal** — the box is
the author's to set, and a collision is legitimate in a relaxation whose outer
layers are frozen.

### 2.4 One rule for the layer spacing

The spacing between atomic layers was computed **in the browser**, as three
literals, and was missing `d(110)` entirely — so building fcc(110) showed you two
spacings, neither of which was the number the Cell page asks you to type.

It is now one rule in `cell.interplanar_spacing`: the cubic formula evaluated at
the **first allowed reflection** for the lattice's centring. fcc allows h,k,l all
the same parity, bcc allows h+k+l even. That is why fcc(100) is `a/2` and not
`a`. A system with no rule (hexagonal) **refuses** rather than returning a
plausible wrong number.

It sits beside `bulk_z_period` and `detect_layers`, which *measure* the same
quantity off atoms — and that adjacency buys a test neither half had: predicted
== measured on a real ASE slab, for all three surfaces.

The browser asks `GET /api/modify/spacings`.

### 2.5 Nothing is implicit (user ruling)

> *"We cannot allow none… It's going to be deceiving. It's going to give the user
> the wrong idea of how this is used."*

Every door returning a spacing **requires** the reference: the word
`experimental`, the word `pbe`, or a number. No default. The two differ ~2% for
gold, which is enough to strain a junction.

Same principle applied to the data file: an override
`$MOLBUILDER_DATA_DIR/fcc_lattice.json` is **honoured or refused, never
half-read**. Before, a trailing comma made it silently return the packaged
4.0782 to someone who had typed 4.20 — and the panel displayed 4.0782 under a
radio labelled "Experimental". *Absence* still falls back; a file that is there
and unreadable does not.

### 2.6 `--electrode` can pick a stacking registry

`junction-cell.md` § 3.1a has recorded since 2026-09-15 that the walk
(`ABC`/`ACB`) does **not** decide the seam — `start_registry` does — and that the
web slab card exposed it while the CLI had no way to say it. The note said to fix
the sentence and the CLI together; only the sentence had been done.

`--electrode Au:111:3x3x3@contact=2.4:registry=B:+z=3`. Accepts `A`/`B`/`C` or an
index; omitting it means registry 0, so **every existing command line is
unchanged**. Measured: the starting layer moves by `a/√6` = 1.665 Å between A and B.

### 2.7 Smaller, same session

- `Structure.to_ase()` handed over atoms alone, so a crystal arrived in ASE as a
  gas-phase cluster (zero cell, `pbc` all false). It now carries the resolved box.
- `concat` took the **whole** non-atom block from whichever input had a cell, so
  appending a slab onto a molecule replaced the user's typed 8 Å vacuum with the
  slab's deliberate zero and turned two isolated axes crystalline — silently. A
  cell and its corner are what a fragment can supply; `axis_kind`, `vacuum` and
  `info` are facts of the canvas.
- Two `dataclasses.replace` calls on a `Structure` were sharing `cell` and the
  `info` dict with their source. `dataclasses.replace` does **not** dispatch to
  `__replace__` on any Python version — it calls `obj.__class__(**changes)` — so
  `Structure.replace` is the only correct door. (A docstring and a test in the
  repo still claim 3.13+ fixes this. They are wrong; see § 4.)
- `replace(pbc=…)` was being silently discarded by the carried `axis_kind`.
- The deck's provenance comment claimed three false things under an explicit cell
  and measured hexagonal `b` 13% short (`np.diag` is the axis length only for an
  orthogonal cell).

## 2a. What changed AFTER this document was first written

Nine more commits, and two of them altered the data model. A reader who stops
at § 2 will have a stale picture.

### `pbc` is no longer a field — `axis_kind` is the only periodicity state

The dataclass had two periodicity fields. `axis_kind` says what an axis IS
(`periodic` / `isolated` / `transport`); `pbc` held the boolean view. The
mapping is onto, not one-to-one — `periodic` and `transport` both give `True` —
so `pbc` could never hold a fact `axis_kind` did not, and `__post_init__`
recomputed it on every construction. It was a duplicate kept in step by a
reconciliation block, and the declaration carried two adjacent comments each
claiming to be the source of truth.

It cost more than redundancy. `replace()` carried both and the kind won, so a
caller stating only the boolean had it silently discarded — patched by
comparing the two *inside* `replace()`, one precedence rule in two places. And
`transiesta` branched on the boolean to label each axis, so **every transport
axis was written into the deck as `periodic`**, and its "transport axis is not
periodic" warning could never fire.

**Now:** `axis_kind` is the one field (15 dataclass fields, not 16).
`Structure.pbc()` is a METHOD — an interop accessor for the only two formats
outside this project that need booleans, ASE's `Atoms(pbc=…)` and the extxyz
`pbc="T T F"` header. **Nothing inside molbuilder calls it**; code that needs
to know how an axis is treated asks `axis_kind`. Contract: § 2.0a of
`structure-periodicity.md`.

**On disk:** `pbc` left `METADATA_FIELDS`, so sidecars stop writing it and it
left the fingerprint. An older sidecar carrying the key is **accepted and
ignored** — `structure.RETIRED_METADATA_KEYS`, read by all THREE gates. That
count is the hard-won part: the sidecar loader refuses stray keys upstream of
`apply_metadata_dict`, the retirement went into the downstream one only, and
for one commit **every pair this project had ever written failed to load**.

> **"Both" was itself one short** *(corrected 2026-09-22, on the merge)*. Both
> machines found this break independently and each saw a different part of its
> extent: `62cc76d0` fixed the loader and `apply_metadata_dict`; the other
> branch fixed those two **and**
> `sidecars.molstruct.apply_to_structure`, which refuses stray keys again
> before applying. Three gates ask the question, and they now read one list.
> The third is not reachable from `StructureCodec.load` — the loader answers
> first — but it takes a payload directly, and a guard that disagrees with its
> neighbours is exactly how this bug happened. The merge kept this document's
> NAME (`RETIRED_METADATA_KEYS`) and the other branch's gate count.
>
> The evidence also changed. This section's "every pair this project had ever
> written" was originally measured by counting files in `projects/`, which the
> standing rule forbids. It is derived from the writer now, which is both
> legal and stronger: `metadata_to_dict` emitted `pbc` on every build before
> the retirement, so every pair carries it, no file tree required.

The
schema version did NOT bump, and should not: verified in both directions that
an old build reads a new file and a new build reads an old one, so bumping
would turn a working read into a refusal.

### `info` is a namespace of clusters, with three doors

`info` was a free-form dict with one conventional key. It is now declared: a
top-level key names a subsystem and owns everything under it, `calculation`
being the one this project ships. The shape was **already decided on the
browser side** — `molview.data.info` has had `set(key, value)` / `remove(key)`
since MolView shipped — and Python had no equivalent, which is why three
callers assigned the whole store by hand.

  * `set_info(key, value)` — one cluster, in place;
  * `drop_info(key)` — one cluster removed;
  * `apply_info_dict(dict|None)` — the whole store, in place (what all three
    existing writers actually wanted);
  * `replace(info=…)` still derives a copy.

Values must be JSON-serialisable, checked on the way in. `from_dict` — the
door the browser reaches through `struct_from_body` — was laxer than the
others until `0fffd55b`; `info: {"": …}` posted to a modify route came back at
HTTP 200 and would have reached the sidecar.

### And the smaller ones

`apply_atom_metadata` (the deck's label block) skipped the validator that the
sidecar path uses — a block naming atom 99 of a 2-atom structure was accepted
and surfaced later on the next `copy()`. It could not simply call
`apply_metadata_dict`, which is a FULL REPLACE against a PARTIAL block, so it
now completes the block first: the same *"complete the block, do not patch the
result"* shape `transport/compose.py` uses.

`replace()` is now pinned **complete by construction** — the test iterates
`dataclasses.fields(Structure)`, so a sixteenth field added tomorrow is
covered the day it is declared rather than silently resetting on every derived
copy.

## 3. The rule this session added to the playbook

`process/code-audit.md` § 1d gained a **step 0**, and it is the thing to carry
forward:

> **Decide something is obsolete by READING, never by a reference scan.**

A grep, an AST pass or `git log -S` establishes reference facts. A reference fact
cannot tell apart the only two things that matter:

| "no caller" can mean | what it is |
|---|---|
| something better replaced it | **residue** — delete it |
| a caller was **lost**, and the rule it carries silently stopped running | **a regression** — restore the call |

Both look identical to every tool. The bar: read the owning module end to end;
read what replaced it and name the rules it covers; read the history for why the
caller went; read the test that keeps it alive.

**This session broke that rule twice and both are instructive.** Removing the
constructor refusal (§ 2.2) orphaned a guard nobody had noticed was load-bearing.
And a reported crash — *"a form-B citation dies in `axis_vacuum` with a raw
`LinAlgError`"* — was asserted by two independent reviews after probing that
function **in isolation**. Traced end to end, it is false: the validator runs
before any geometry is emitted, so the deck path answers
`[cell.no_volume] This box is flat`. The fix was still right, for a different and
smaller reason (the refusal lands at the citation door, in the citation's words),
but the stated consequence was wrong in a commit message, a docstring and a test
until it was checked.

## 5a. The loose ends this session chose not to pull

These are NOT in `plan.md` § 2, because they are smaller than a row and would
clutter it. They are here so they are not lost. Each says what is known, what
is not, and why it was left — none of them is urgent, and none should be done
by pattern-matching without the read the entry asks for.

**① `replace()` still hand-enumerates, and that is now only half a problem.**
`Structure.replace()` names nine fields in a literal and gets five more from
`_carry_nonatom()`. Completeness is now PINNED — `test_replace_carries_every
_field_the_dataclass_declares` iterates `dataclasses.fields()`, so a
sixteenth field forgotten in both lists fails immediately. What is *not*
fixed is the shape: it is still an enumeration, and the door exists because
enumerations drop fields. Deriving the carried set from `dataclasses.fields()`
directly would make it complete by construction rather than by a test. Left
because the test closes the actual risk and the refactor touches the single
most load-bearing method in the model. **Do not attempt it without reading
`replace()`, `_carry_nonatom()` and `__post_init__` end to end** — `frozen_atoms`
must stay excluded, and the reason is subtle (the property has no storage;
a copied `regions` already carries the reserved label).

**② `frozen_atoms` is the same shape `pbc` was, and is benign.** An `__init__`
field shadowed by a property over `regions[FROZEN_LABEL]`. Unlike `pbc` it
holds no independent state — every read and write goes through `regions`, so
the two can never disagree, and it needs no special case in `replace()`. The
init-field spelling exists so `Structure(…, frozen_atoms=[…])` reaches the one
place that spells the reserved label. **Recorded so nobody "fixes" it by
analogy with `pbc`.** It is not the same defect.

**③ The CLI still returns no seam verdict.** `_seam_notices` has one caller,
the web slab route. Raised and **DROPPED on the user's ruling** — *"people
working with CLI would know what they're doing… leave that out."* Listed only
so it is not re-proposed. X3 is the browser half and is still open.

**④ `apply_metadata_dict` is full-replace, and partial writers must complete
the block.** Two callers now do this (`transport/compose.py` applying a sidecar
over a `.XV`, and `script_emit.apply_atom_metadata` for a deck's label block).
There is no partial door and probably should not be — full-replace is what
makes "an absent key resets to default" legible. But a third partial writer
will hit the same wall, and the pattern it should copy is *complete the block,
do not patch the result*. Worth a line in `structure.md` § 2.2 if a third one
appears; not worth inventing an API for two.

**⑤ Two `.molstruct.json` readers exist by format, and only recently by
validation.** `apply_metadata_dict` reads the sidecar; `apply_atom_metadata`
reads the deck's in-body block. A reader per format is right. They now share
the validator, which they did not before. The remaining question — whether the
deck block should exist at all, or whether a deck should carry only a pointer
to the pair — belongs with the other machine's structure-I/O plan, not here.

**⑥ The `info` cluster namespace has one declared member.** `calculation` is
the only cluster this project writes. The namespace rule is stated and the
doors enforce it, but nothing yet exercises a SECOND production cluster, so
the isolation property is pinned only by tests. That is fine — it is the right
shape to have in place before the second subsystem needs it — but the first
real second cluster is worth watching, because it is the first time the rule
will be load-bearing outside a test.

**⑦ Verification habits this session had to learn the hard way**, listed
because they cost real defects:
  * Four times a whole-suite run caught what a file-scoped run structurally
    could not — a membership assert over every route, three tests in a file
    not selected, an annotation round-trip, a two-gate sidecar break.
  * Twice a clever structural scan reported clean while blind to the shape
    being searched for: an AST pass over `.pbc` attribute nodes missed four
    sites (a `getattr` off a name tuple, a dict key, a constructor kwarg, a
    string in a set); a "cannot fail" scan said 36, then 1, then 0.
  * Verifying the dict path and calling it verification of the file path is
    how the retired-key break shipped. **Exercise the door the user's data
    actually goes through.**

## 5b. What the merge found — four defects, and a documentation class

*(2026-09-22, the other machine, after § 5a was written. Each was measured on
a fixture before it was acted on; `projects/` was not read.)*

The two branches merged cleanly on the code and left four semantic
disagreements that no test caught. Three of them came from the structure-I/O
branch; one was live on `main`.

**① A dead `or` that was not harmless.** `transport/compose.py` read
`_side.get("axis_kind") or ["periodic","periodic","transport"]`. It could
never fire: `load_sidecar` normalises the payload through a scratch
`Structure`, and `__post_init__` always fills the kinds — so a sidecar that
states none arrives as `["isolated"] * 3`, which is truthy, and the sidecar
won every time. An authoring pair saved before a box was committed carries
`isolated`, so the emitted deck read `c (transport)  isolated` and shipped
*"the transport axis has vacuum / is not periodic"* about a junction open
along z by construction — **the regression the eighteen-line comment above
those lines says it fixed, live again through the sidecar branch.** Now
stated outright (§ 5 I8). This is § 2a's own lesson recurring one level up:
verifying the dict path is not verifying the file path.

**② The authoring corner travelled again, on a new path.** `xv2xyz
--from-run` applies a sidecar over a `.XV` — the same operation `compose.py`
strips `cell_origin` for — and kept it. Measured: an authoring corner of
(49,49,49) over a `.XV` whose atoms sit at (1,1,1) emitted every atom at
**−48 Å**. § 2.1's defect, third instance, written by someone who had read
§ 2.1. The rule needs to be reachable from the code that performs the
operation, not only from the document.

**③ A non-finite `.XV` cell escaped as a bare `ValueError`.** `float("nan")`
parses, so the parser's `try/except` never saw it; once the reader began
putting the cell on a `Structure`, `__post_init__` refused it where every
caller catches `SiestaXVError` only — a CLI traceback, and HTTP 500 on the
compose route. The parser refuses it now, in its own error type.

**④ One fallback disagreeing with ten.** `transiesta.py` answered
`("periodic",)*3` for a missing `axis_kind` where every other site —
including `Structure.pbc()` — answers `("isolated",)*3`. It arrived as the
literal swap for the old `struct.pbc` field read. All eleven are unreachable
(`__post_init__` always fills the kinds); this is the one whose waking would
relabel every axis in a deck. **Left open:** the other ten `axis_kind or …`
fallbacks are dead code that should probably just go, but that is eleven
reads, not a sweep to do by pattern.

**And a documentation class, which is D5's.** Ten places still described
`pbc` as a stored field after it stopped being one — two of them stating the
dependency *backwards* (`_carry_nonatom`: *"axis_kind -> derived from pbc"*;
the field declaration itself). The first pass found five, because it searched
the two files already open; re-scanning after the fix found four more, plus a
line wrap the fix had broken. **A count is a hypothesis.**

## 6. Standing constraints worth restating

These are the user's, and they governed everything above.

- **`projects/` is real research data.** Never read, grep, count, parse or cite it
  as evidence. Build a fixture; derive numbers from the writer.
- **A green test proves nothing until the code is broken and the test observed
  failing.** Every fix in this range was mutation-checked. *(One caution: a
  mutation harness with an unquoted `-k` selector will word-split a `'A or B'`
  expression, pytest errors, and the run reads as a false SURVIVED. Quote it.)*
- **Run the full suite before saying done.** 583 targeted tests were green while a
  membership assert that enumerates the whole app was failing — a file-scoped run
  cannot see it.
- **Do not be the user's nanny.** A warning is a warning; the box, the lattice
  constant and the geometry are the author's to set. Bad contacts show up in the
  calculation as bad contacts.
- Tests run under the `molbuilder` env via `tools/testrun.py`. Never pipe it
  through `tail`/`head`. Never `git checkout` to undo an edit — copy to a
  scratchpad first.
