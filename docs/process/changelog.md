# Changelog — what each version changed in the files molbuilder writes

**Role:** record
**Domain:** process

One line per version, newest first: what changed in which file molbuilder
writes, and the date. The rule for when the version moves is
[`conventions.md`](?doc=process/conventions.md) § 2, *Versioning*; every deck
and run script records the version that wrote it
([`execution/job-contracts.md`](?doc=execution/job-contracts.md) § 3.2).

| version | date | what changed |
|---|---|---|
| **2.10.0** | 2026-10-14 *(RMP, plan § 5ab — R1 to R6, R4 dropped)* | **New: the order a structure's atoms are in is recorded, and you are always shown and given your own** — a middle-number move, new functionality ([`conventions.md`](?doc=process/conventions.md) § 2; [`model/overview.md`](?doc=model/overview.md) § 2.2a). A structure an engine needs in another order — a SIESTA vibration's held atoms first, TranSIESTA's electrode blocks — carries its **order record**, `atom_order`, the key that made it and both directions: in the `.molstruct.json` (**sidecar v14**, `null` in your order; v7–v13 read as your order) and in every deck written from it (its ATOM-METADATA block, which now carries every metadata field but the box, and is written whenever it has a label, a channel, a named value or an order record — a block of named values alone was dropped by the run door). **Every door that crosses back restores**: the Molbuilder tab's load and Add, `molbuilder modify` (its agreement saying the atom indices count in your order), the save, the download and the hand-over, `jobset init`, `xv2xyz --from-run` — each saying so (*… was in an engine's order (held atoms first); it is put back in your order*); no pair is written for a person in an engine's order (the codec refuses, but for the transport composer's junction). **A viewer holding a run in its engine's order says so** above its tabs; SIESTA's own `<label>.xyz` in a run opens through the run's view, with its labels and order; a bare `xv2xyz` of a reordered run's `.XV` is refused, naming `--from-run`; `watch parse`, `watch tail` and `runtime-info` say when a file's run is in its engine's order. **A deck prepared before 2.10.0** for a kind that reorders states no order: `xv2xyz`, `jobset init`, `molbuilder modify` and the Molbuilder tab's open refuse it; the Results tab and the bare readers say so, and a save, download or hand-over from the Results tab writes it as the engine listed it; launch, refusing a stage prepared from another description, names the molbuilder that prepared it — prepare it again. **A SIESTA vibration's force-constant stage takes the relaxation's coordinates through the run's own order record**; prep and a transport citation refuse a run prepared before 2.10.0 whose order nothing states. **A calculation's structure edited after it was described** — a coordinate, a label, a held atom, the box — is refused at prep: the description records the structure's fingerprint (describe it again to build on the edit). **A transport calculation citing a run that relaxed no geometry** — a vibration's force-constant stage, a transport rung — is refused by name. Every message that names atoms of a deck's sorted copy — a held set's warning, an atom outside the box, a lead that moved — names them in your order. The relaxation record drops `held_atom_idxs` (its held atoms are named by their lines). **`atom-permutation.json` is no longer written**: a SIESTA vibration's finish reads its order record from its own deck, and a transport calculation's composition record from its junction's sidecar. **A transport calculation's data file states its atoms in your order** (`molbuilder/transport-data@2`); its record names no permutation file; a vibration's force-constant range is named as SIESTA's numbering, `fc_range_engine_1based`, in its result (`schema_version` 8; a v7 result still reads, its range under the new name) and in the displacement sweep's record (`molbuilder/fc-displacement-sweep@2`) — `summarize task` writes the records again. **A calculation carries across an upgrade of molbuilder** (UPG): a run is taken by the next stage when it ran the same engine input as the deck its stage renders now — comments and molbuilder's records aside, an explicit engine default (the catalogue's `engine_default`, with its source line) the same as none, the geometry within 10⁻⁶ Å — and the gather's refusal names the first difference, never a version; what a file holds is read from what it states, never from the molbuilder that wrote it. A transport junction whose sidecar states no order record is composed again in memory by the next prep and, the same junction atom for atom, given its order record — `prep task` with no group left to prepare records it too; a prep never replaces a junction a launched stage ran on. Until then its data file and a selection's PDOS are refused by name, naming `prep task`, and the report says so (`molbuilder/transport-result@7`). **The transport report draws its junction in your order**, and a projected-DOS selection is named in your order, asked and answered (`/api/transport/pdos`). *A pair saved before 2.10.0 from a reordered run's view is in the engine's order with nothing to say so, and cannot be told apart.* |
| **2.9.6** | 2026-10-13/14 | **Step 1 of the plan's order — places where a result could be wrong or lost unsaid** — a last-number move ([`conventions.md`](?doc=process/conventions.md) § 2). The Results tab's file card, for a file of a calculation whose `task.json` its reader refuses, says whose file it is cannot be said there and gives the reader's own words, the way out among them (`jobset migrate`) — it said *not written by molbuilder* for every file ([`web/results.md`](?doc=web/results.md) § 3b). A live run's movie follows a poll that rebuilds it — the trajectory viewer's install says it replaces what its read-only viewer shows (`enforce`, [`web/molview.md`](?doc=web/molview.md) § 9.4); every rebuild after the first load, and every Reload, was refused in silence, the frame counter growing over the old frames ([`web/trajectory.md`](?doc=web/trajectory.md) § 5). **SIESTA's history is each run's own**: `.MD.nc`, `.MD`, `.MDE` and `.ANI` are named for the run that wrote them — `<label>_<stage>-run<N>.MD.nc` and its three siblings, in either shape — the run script pointing SIESTA's name for each at the run's file while the engine runs and removing the pointer when it exits ([`execution/job-contracts.md`](?doc=execution/job-contracts.md) § 2.2, § 2.6); a continuing stage carries none (`siesta/warm-files.toml`), and a run's frames are sharpened from its own history — a flat stage launched again took the earlier run's rows ([`model/parse.md`](?doc=model/parse.md) § 5a). A folder where SIESTA's name already holds a history file, kept so before 2.9.6, stops a run before its engine starts, naming the file to move aside; a run made before 2.9.6 is shown from its output's own values. **A warm retry's session log is its own**: the run script hands back the output it was started with before it starts again, so the first try's `.runwrap-<stamp>.log` holds the first try alone — it held the retry's too ([`execution/running-a-job.md`](?doc=execution/running-a-job.md) § 3.5); a TBtrans run's script carries no retry, its banner saying *none -- TBtrans runs no SCF and no relaxation* where it promised retries on non-convergence. **A structure is pinned to its geometry** (sidecar v13, plan V1.9 / M2m): every pair molbuilder writes has its `.molstruct.json`, a plain molecule's included, carrying `geometry_hash` — the sha256 of the atom lines as written and the cell and axis kinds, never the comment line — in place of `structure_hash`, retired (read, never written); the one read door compares it, so prep refuses a calculation whose structure's atoms or cell changed after it was described, as do `jobset init`, the CLI and a citation, while the Molbuilder and Results tabs open such a pair saying so (`structure.geometry_changed`) and saving it writes the pair anew ([`model/structure-molstruct.md`](?doc=model/structure-molstruct.md) § 3). A pair saved before 2.9.6 opens unchecked. A PySCF run's `<label>_optimized.xyz` is read in the Results tab through the same door, with the labels and cell its sidecar states — it was read as atoms alone. **`X` is not an element**: ASE's dummy atom, at Z = 0, is refused by the one element lookup like any name that is not one — a SIESTA deck wrote it as `1 0 X`, a ghost species, and the electron count took it as nothing ([`model/chemistry.md`](?doc=model/chemistry.md) § 3). The pair handed over as named bytes takes the format its name names, as a save does: `mol.pdb` is a PDB, where it was XYZ under `mol.pdb.xyz`; a download stays plain XYZ ([`model/structure.md`](?doc=model/structure.md) § 2.4). **A broken record is refused, not read as nothing**: a sidecar's annotation channel with no `kind` is refused naming the file and the channel — it escaped as a bare `KeyError('kind')`; a deck's molbuilder block that cannot be read — its fences unpaired, no JSON object, JSON that does not parse — is refused naming the deck and the way out (`molbuilder checkpoint restore`, or the stage prepared again), on every surface: a broken ATOM-METADATA read as a deck with no labels, and the run was shown without them ([`execution/job-contracts.md`](?doc=execution/job-contracts.md) § 3.1). **Holding more atoms for the spectrum than the relaxation held is information, not a warning**: a vibration's check against the structure's relaxation record warned on any different held set, saying the geometry was not stationary — for a partial Hessian over fewer atoms, each balanced by the relaxation, it is; the finding now names only an atom the relaxation held that the vibration frees — a warning when the box is ticked, information when not — ([`engines/vibration.md`](?doc=engines/vibration.md) § 2.3a, and the same for transport in [`engines/transport.md`](?doc=engines/transport.md) § 1.1, Step 0); and a PySCF vibration's record findings name its own relaxation, the deck's Phase 0, where they spoke of a SIESTA ladder |
