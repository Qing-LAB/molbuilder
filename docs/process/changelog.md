# Changelog — what each version changed in the files molbuilder writes

**Role:** record
**Domain:** process

One line per version, newest first: what changed in which file molbuilder
writes, and the date. The rule for when the version moves is
[`conventions.md`](?doc=process/conventions.md) § 2, *Versioning*; every deck
and run script records the version that wrote it
([`execution/job-contracts.md`](?doc=execution/job-contracts.md) § 3.2).

| version | date | what changed |
|---|---|---|
| **2.11.2** | 2026-10-18 | **The suite's result no longer depends on how many workers run it** — a last-number move ([`conventions.md`](?doc=process/conventions.md) § 2). Two tests of `test_describe.py` set `$MOLBUILDER_PROJECTS` by hand and deleted it after, whatever was there; since 2.11.0 spread a file's tests over the workers, which tests followed them in a worker changed with the worker count, and the two tests of the projects root's resolution (`test_seeding_a_fresh_machine.py`) passed or failed by it. They set it through `monkeypatch` now, which puts back what was there, and the suite clears your shell's `$MOLBUILDER_PROJECTS` for the session, so no test reads your tree ([`testing.md`](?doc=process/testing.md) § 2a). And the test of a spread run checked the rule 2.11.0 retired — every file whole on one worker — on a file whose tests share nothing, so it passed or failed by where xdist put them; it checks the rule now: a file whose tests share a fixture runs whole (§ 6.1a). |
| **2.11.1** | 2026-10-18 | **A playing movie asks the server nothing for the frames it passes** — a last-number move ([`conventions.md`](?doc=process/conventions.md) § 2) *(the user, 2026-10-18: "why does playing animation need a request to the server?")*. Playback moves the frame through the one write, so what follows the frame still redraws at each — drawing is local; what asks the server about the frame shown now waits for the frame playback stops on: MolView's view context writes nothing while the movie plays and writes once when it stops, and the transport report's charts follow each frame from its record while each selection's PDOS is asked once, at the stop. The viewer's handle announces playback once per start and once per stop (`onPlaybackChange`), never on a restart at a new speed ([`molview.md`](?doc=web/molview.md) § 9.2, § 11.2b; [`results.md`](?doc=web/results.md) § 2.5). |

Launch runs the command the calculation's copy of the record names; the header says what the scheduler tells the job once in molbuilder's names (`MB_NTASKS`, …), so the run script is one file on every machine. **Re-probe each machine** (`molbuilder jobset probe --write`, on Sol too): an older record is refused by name; a prepared calculation's copy is rewritten by `jobset migrate` ([`scheduler.md`](?doc=execution/scheduler.md) § 6a, [`configuration.md`](?doc=configuration.md) § 5 M-2). |
