# Changelog — what each version changed in the files molbuilder writes

**Role:** record
**Domain:** process

One line per version, newest first: what changed in which file molbuilder
writes, and the date. The rule for when the version moves is
[`conventions.md`](?doc=process/conventions.md) § 2, *Versioning*; every deck
and run script records the version that wrote it
([`execution/job-contracts.md`](?doc=execution/job-contracts.md) § 3.2).

| version | date | what changed |
|---|---|---|
| **2.9.6** | 2026-10-13 | **Step 1 of the plan's order — places where a result could be wrong or lost unsaid** — a last-number move ([`conventions.md`](?doc=process/conventions.md) § 2). The Results tab's file card, for a file of a calculation whose `task.json` its reader refuses, says whose file it is cannot be said there and gives the reader's own words, the way out among them (`jobset migrate`) — it said *not written by molbuilder* for every file ([`web/results.md`](?doc=web/results.md) § 3b). A live run's movie follows a poll that rebuilds it — the trajectory viewer's install says it replaces what its read-only viewer shows (`enforce`, [`web/molview.md`](?doc=web/molview.md) § 9.4); every rebuild after the first load, and every Reload, was refused in silence, the frame counter growing over the old frames ([`web/trajectory.md`](?doc=web/trajectory.md) § 5). **SIESTA's history is each run's own**: `.MD.nc`, `.MD`, `.MDE` and `.ANI` are named for the run that wrote them — `<label>_<stage>-run<N>.MD.nc` and its three siblings, in either shape — the run script pointing SIESTA's name for each at the run's file while the engine runs and removing the pointer when it exits ([`execution/job-contracts.md`](?doc=execution/job-contracts.md) § 2.2, § 2.6); a continuing stage carries none (`siesta/warm-files.toml`), and a run's frames are sharpened from its own history — a flat stage launched again took the earlier run's rows ([`model/parse.md`](?doc=model/parse.md) § 5a). A folder where SIESTA's name already holds a history file, kept so before 2.9.6, stops a run before its engine starts, naming the file to move aside; a run made before 2.9.6 is shown from its output's own values. **A warm retry's session log is its own**: the run script hands back the output it was started with before it starts again, so the first try's `.runwrap-<stamp>.log` holds the first try alone — it held the retry's too ([`execution/running-a-job.md`](?doc=execution/running-a-job.md) § 3.5); a TBtrans run's script carries no retry, its banner saying *none -- TBtrans runs no SCF and no relaxation* where it promised retries on non-convergence |

Beside it: `jobset launch --mode direct` waited on now reads each run's state through the one status door and exits 1, its line saying *FAILED* in the status's own words, when a run did not finish — it exited 0 whatever happened ([`execution/job-system.md`](?doc=execution/job-system.md), *A run here, waited on*); the Results tab's SCF plot draws every residual the engine converges on — SIESTA's dDmax and dHmax, a NEGF loop's dQ, PySCF's dE and \|g\| — each in its own unit and against its own tolerance line, where it drew dHmax alone -- each line's label on its line (a label on a log axis had been placed at 10^value) and the legend under the axis title, the chart theme's one rule for every small chart (`legendBelow`, `thresholdMark`), the max-force chart's target label on a log axis with it; each engine's residuals are declared once and served with every run (`runtime_info.scf_residuals`, [`web/trajectory.md`](?doc=web/trajectory.md) § 3.0) |

Save sits in a bar pinned to the bottom of the window that says whether the page's text is on disk (§ 7a); *Preparing, group by group* is two cards in the order of the work — *What each group runs*, then *Prep the task* — and the `task.json` editor comes last (§ 11). A parameter picker no longer runs 3 px past a phone's width |
| 2.9.3 | 2026-10-13 | **The server runs one numerical thread** — a last-number move ([`conventions.md`](?doc=process/conventions.md) § 2); no file molbuilder writes changes. | 2.9.0 | 2026-10-13 | **The k-point wording, one vocabulary** (the user: "the language are vague to state k-point, k-grid or mesh etc inconsistently"): every deck's k-point comments and block titles, and every k-point finding in `.validation.txt`, now say *k-point grid* (never *mesh*, which in SIESTA is the real-space grid of `MeshCutoff`), *in the electrode plane (x, y)* and *along z* (never *transverse*), with each reason in full sentences; the items' labels read *k-point grid*, *k-point grid offset*, *Lead k-points along z* and *Transmission k-point grid (x, y)*. | 2.8.0 | 2026-10-13 | **A transport calculation's transmission mesh is three times the shared one until the person sets it** ([`engines/transport.md`](?doc=engines/transport.md) § 0.2–0.3b): the template writes `tbt_k_grid` blank — *not chosen* — where Describe wrote three times the cited or the person's mesh and recorded it as the citation's or the person's; the transmission deck's `TBT.k` is worked out when the deck is written, so it follows `kgrid`, with a comment beside the block and its provenance row saying so (*not chosen · three times the k-point mesh in the electrode plane*). | 2.7.0 | 2026-10-11 | **Every stage states its group; prep prepares any groups at once, and a group's first launch takes what its members build on** — the rules are [`execution/job-system.md`](?doc=execution/job-system.md), *The task*. What changed in the files and commands: `task.json`'s stages each carry **`group`** — a description without them is refused, naming `molbuilder jobset migrate`, which writes them and keeps the old file as `task.json.pre-2.7.0`; `job-set.json`'s jobs carry **`written_at`** (a SIESTA force-constant stage's `relax` run) and **`asked`** (what its prep was told beside the description), and a job's member list is the key **`members`** — `jobset migrate` renames `group` and fills the new keys, keeping `job-set.json.pre-2.7.0`; a job set migrated from before 2.7.0 records nothing its prep was told (`asked` empty), so a stage prepared then with launch flags (`--np`, `--time` …) is refused at its first launch, naming its prep again, and a SIESTA force-constant stage prepared then has no recorded `relax` run (`written_at`), so its first launch asks for its group to be prepared again; a group of several has its one header in the calculation's `launch/` folder; `prep task --group N` (repeated) replaces `prep task --stage`, and prep takes no `--cold` (what a stage takes is its launch's); `launch task --group N` sends a group, and `launch task --stage` one stage launched again; prep copies nothing from another stage's run: `.continued-from` and `.gathered-from` are written by the launch, with what it copies; the folder's state is saved at a group's first launch too (`… · before launch task group 2 (medium, tight)`), and prep's note names each group with its members; `STAGE-PLAN.md` lists each stage's job mates and what each prepared stage takes at its first launch; a swept transport run reads *finished* when every point's run finished, its convergence in its own column; prep's next line is the bare `launch task`; a deck's header names its group's first launch (`launch task`) and the stage alone (`launch task --stage <it>`), and a run script's banner, usage and retry lines name a launched stage's way back as the state saved before its group's first launch; a `.sbatch` header names `jobset launch` and the hand form past the run script's gate (`sbatch --export=ALL,MB_LAUNCHED_BY=manual … --run N`) |
