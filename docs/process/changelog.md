# Changelog — what each version changed in the files molbuilder writes

**Role:** record
**Domain:** process

One line per version, newest first: what changed in which file molbuilder
writes, and the date. The rule for when the version moves is
[`conventions.md`](?doc=process/conventions.md) § 2, *Versioning*; every deck
and run script records the version that wrote it
([`execution/job-contracts.md`](?doc=execution/job-contracts.md) § 3.2).

| version | date | what changed |
|---|---|---|
| **2.9.0** | 2026-10-13 | **The k-point wording, one vocabulary** (the user: "the language are vague to state k-point, k-grid or mesh etc inconsistently"): every deck's k-point comments and block titles, and every k-point finding in `.validation.txt`, now say *k-point grid* (never *mesh*, which in SIESTA is the real-space grid of `MeshCutoff`), *in the electrode plane (x, y)* and *along z* (never *transverse*), with each reason in full sentences; the items' labels read *k-point grid*, *k-point grid offset*, *Lead k-points along z* and *Transmission k-point grid (x, y)*. The values written are as in 2.8.0 |
| 2.8.0 | 2026-10-13 | **A transport calculation's transmission mesh is three times the shared one until the person sets it** ([`engines/transport.md`](?doc=engines/transport.md) § 0.2–0.3b): the template writes `tbt_k_grid` blank — *not chosen* — where Describe wrote three times the cited or the person's mesh and recorded it as the citation's or the person's; the transmission deck's `TBT.k` is worked out when the deck is written, so it follows `kgrid`, with a comment beside the block and its provenance row saying so (*not chosen · three times the k-point mesh in the electrode plane*). A description written before 2.8.0 keeps the value it holds, as recorded. Every transport deck's k-point comments give the corrected reasons (the leads and the device sampled alike because the lead is the bulk of the device's electrode region; a lead's points along z decide its Hamiltonian and Fermi level). `.validation.txt` warns a lead's `electrode_kz` below 50 (the SIESTA manual's floor; it was 20), and a transmission mesh set coarser than the shared mesh |
| 2.7.0 | 2026-10-11 | **Every stage states its group; prep prepares any groups at once, and a group's first launch takes what its members build on** — the rules are [`execution/job-system.md`](?doc=execution/job-system.md), *The task*. What changed in the files and commands: `task.json`'s stages each carry **`group`** — a description without them is refused, naming `molbuilder jobset migrate`, which writes them and keeps the old file as `task.json.pre-2.7.0`; `job-set.json`'s jobs carry **`written_at`** (a SIESTA force-constant stage's `relax` run) and **`asked`** (what its prep was told beside the description), and a job's member list is the key **`members`** — `jobset migrate` renames `group` and fills the new keys, keeping `job-set.json.pre-2.7.0`; a job set migrated from before 2.7.0 records nothing its prep was told (`asked` empty), so a stage prepared then with launch flags (`--np`, `--time` …) is refused at its first launch, naming its prep again, and a SIESTA force-constant stage prepared then has no recorded `relax` run (`written_at`), so its first launch asks for its group to be prepared again; a group of several has its one header in the calculation's `launch/` folder; `prep task --group N` (repeated) replaces `prep task --stage`, and prep takes no `--cold` (what a stage takes is its launch's); `launch task --group N` sends a group, and `launch task --stage` one stage launched again; prep copies nothing from another stage's run: `.continued-from` and `.gathered-from` are written by the launch, with what it copies; the folder's state is saved at a group's first launch too (`… · before launch task group 2 (medium, tight)`), and prep's note names each group with its members; `STAGE-PLAN.md` lists each stage's job mates and what each prepared stage takes at its first launch; a swept transport run reads *finished* when every point's run finished, its convergence in its own column; prep's next line is the bare `launch task`; a deck's header names its group's first launch (`launch task`) and the stage alone (`launch task --stage <it>`), and a run script's banner, usage and retry lines name a launched stage's way back as the state saved before its group's first launch; a `.sbatch` header names `jobset launch` and the hand form past the run script's gate (`sbatch --export=ALL,MB_LAUNCHED_BY=manual … --run N`) |
| 2.6.0 | 2026-10-11 | **A structure entering a new calculation is centred in its cell unless its origin is a person's** (`model/structure-periodicity.md` § 6.0, *Entering a new calculation*): prep takes a calculation's structure, and a transport junction composed from its citation, without an origin the engine stated, so the one rule places the atoms — the `.source` pair is written as given, with its origin's record; a person's assigned origin is kept, and a vibration's input stated relaxed keeps the engine's frame. A cited run's junction is therefore always centred, and the decks of a new transport calculation place it so. **The structure sidecar is v12**: `offset_by` records whose a stated `engine_offset` is (`person` or `engine`); a v7–v11 file's stated offset reads as the person's, and a save writes it so. **2.5.0's `centre_junction` is retired**: a description holding it is refused, and `molbuilder jobset migrate` removes it, keeping the old file as `task.json.pre-2.6.0`; `slot-provenance.json` no longer records it. **Which config file answered** — the table `STAGE-PLAN.md` and the pipeline log carry — no longer lists a `_`-key of `molbuilder.json` (a comment, `execution/architecture.md`) as a value the file supplied |
| 2.5.0 | 2026-10-11 | **A transport description is written by its describe door, in one act** (`engines/transport.md` § 3.8.2a): `/api/transport/describe` writes the template and `task.json` itself, through the writer `jobset init` takes, into a folder that holds no description — the browser wrote the server's text before. `task.json` now records **`swap_electrodes`** when the Transport tab holds the rename (its request never carried it, so a description written there stated none) and **`centre_junction: true`** when the person centres the junction: this calculation's own copy then states no offset, and every rung's deck places it centred in its cell (§ 4). A transport description's stages are its five rungs in order, the seed the one it may leave out, refused otherwise. A template's launch items carry **`run_card = true`** (`mpi_np`, `omp_threads`, `threads`, `use_gpu`, `gpu_count`; `engines/template.md` § 5), so every run card stands those rows. `slot-provenance.json` records `centre_junction`. A transport template citing a run records its pseudopotential directory as the citation's (`source = "cited"`), since the run's pseudopotentials travel with it. |
| 2.4.0 | 2026-10-11 | **A spin-polarised transport record states each spin and their total** (`web/results.md` § 2.5): each point's `transmission_total` (T↑ + T↓) beside its `channels`, `current_by_spin_a`, and a DOS read from both `<label>.TBT_UP.nc` and `.TBT_DN.nc` — every quantity summed over spin, each spin's own total and eigenchannels in `dos.by_spin`; the I–V block's `current_up_a` and `current_down_a`. `<label>.transport.nc` holds a polarised point's DOS, summed, where it held the fill value. A non-polarised record is written as before |
| 2.3.0 | 2026-10-11 | **The device's deck states TranSIESTA's charge check**: `TS.SCF.dQ.Converge` (on, TranSIESTA's default) and `TS.SCF.dQ.Tolerance` (blank is not set — TranSIESTA's thousandth of the electrons on the atoms that are not buffer atoms, said in its not-set comment), two device settings (`engines/transport.md` § 2a.13). Asked for by a run that could not finish: its density had stopped changing 2.3 electrons off, and SIESTA writes the Hamiltonian the transmission reads only on convergence. **Every JSON file is valid JSON**: a number an engine printed unreadably (a Fortran overflow, read as NaN) is written `null` — not stated — where it was written `NaN` (`persist.json_safe`; `job-contracts.md` § 6.1) |
| 2.2.0 | 2026-10-11 | **A deck's `.validation.txt` states the H/heavy ratio as a reference note on every structure** — `info [geometry.h_ratio]: H/heavy atoms: 4/14 = 0.29 (for reference: organic molecules usually sit at 0.6-1.5)`, counted by element — where it carried a warning below 0.3 that asked whether hydrogens were missing (`science/overview.md` § 4; `f86627b6`). The decks are written as in 2.1.0. *(Version moved in its own commit, after the change: the rule was missed at `f86627b6`.)* |
| 2.1.0 | 2026-10-11 | **A template records the version that wrote it** (`written_by`, `engines/template.md` § 3). **Blank and 0 are two answers on the two device broadenings** (`negf_neq_eta_ev` → `TS.Contours.nEq.Eta`, `tbt_contours_eta_ev` → `TBT.Contours.Eta`): blank is not set — no line, and the program takes a tenth of the leads' broadening, said in the not-set comment — and 0 is written as 0, no broadening. Before, a 0 there meant not set; a calculation written before 2.1.0 that holds one — in its template or as a rung's override in `task.json` — is refused, and `molbuilder jobset migrate` rewrites it blank (`engines/transport.md` § 2a.13). **New lines in the transport decks**: the device's `TS.Contours.nEq.Fermi.Cutoff` (5 kT, refused below 2.5), `TS.SolutionMethod` (`BTD`, or `full`) and `TS.Hartree.Fix C`; the transmission's `TBT.SolutionMethod BTD`; comments on `bloch 1 1 1`, the reservoirs' shared temperature, and tbtrans's own input log. `electrodes_bulk` is carried by the device and transmission only (`stages`) |
| 2.0.0 | 2026-10-11 | **The first release since 1.1.0** (tag `v2.0.0`). Every deck and run script records the version that wrote it (`generator-version 2.0.0 (git …)`); a file written before records only its git commit and reads as *before 2.0.0*. Each deck's provenance block lists who set each value it is rendered from (`parameters:`), and a setting left to SIESTA or PySCF says so where its line would be (`# <keyword> not written: …`) — `engines/template.md` § 6.6, `job-contracts.md` § 3.2. Everything between 1.1.0 and 2.0.0 is in `git log v1.1.0..v2.0.0` and the plan's archive (`docs/archive/`) |
