### ROGUE findings, worst first

1. **A real HTTPS POST to Slack.** `tests/test_notify_setup_api.py:692-707`, parametrize row `("post", CH + "/lab/test", None)` at line 696. `test_no_verb_hands_out_a_secret` stores `lab` as `WEBHOOK = "https://hooks.slack.com/services/T0/B0/AbCdEfGhIjKlMnOp"` (lines 45 and 702), then POSTs the channel's Test route without faking `urlopen`. Every other test-route case in the file fakes it. The route (`molbuilder/web/blueprints/notify_setup.py:477-480`) calls `urllib.request.urlopen(req, timeout=TEST_TIMEOUT_S)`. **Reaches:** the network, a real notify host, on every run.
2. **Reads the developer's real config dir through a module-scoped server.** `tests/test_pages_no_js_errors.py:43-47`. The module-scoped `flask_server` calls `support.live_server.serve()`, which builds `create_app(config={})` before the function-scoped isolation runs, and nothing calls `outside_the_developers_folders`.
   - `create_app` calls `diagnostics.initialize()` (app.py:305), which runs `detect()`, then `read_config()` (diagnostics.py:410). That reads the real `~/.config/molbuilder/molbuilder.json`, or `$MOLBUILDER_CONFIG_DIR` if the shell sets it, and runs the real conda.
   - `read_notify_keys()` (app.py:452-453) reads the real `secrets/notify-keys` and registers the developer's real listener route and keys in the test server.
   - `serve()` also makes its tree with `tempfile.mkdtemp` in the system `/tmp`, outside `tmp_path` (live_server.py:47), and sets `os.environ` by hand.
   - **Reaches:** `~/.config/molbuilder` (read) and the real conda.
3. **Reads the real config at collection time.** `tests/_road.py:105-133`. `conda_hook()`, `env_available()` and `env_bin()` call `diagnostics.detect()`, which reads `config_dir()/molbuilder.json` and lists the real conda envs. e2e modules call them at import or in `skipif`, before any fixture has redirected anything: `test_vibration_e2e.py:29` (`CONDA_SH = conda_hook()`), `test_wall_reaches_the_engine_e2e.py:30`, `test_siesta_optimization_run_e2e.py:39`, `test_transport_on_a_real_junction_e2e.py:69`, `test_siesta_on_the_gpu_e2e.py:28`. **Reaches:** `~/.config/molbuilder` (read) and the real conda, on every collection.
4. **Half-isolated real-engine runs.** `tests/_road.py:166-187` (`_live`), used by module-scoped e2e fixtures. It isolates the config and state roots (`outside_the_developers_folders`, then `write_machine_record`), but leaves three things to the caller while a real-engine run is launched from module setup:
   - `HOME` stays the developer's;
   - `XDG_RUNTIME_DIR` stays the developer's, which holds the live dev server's `serve-<port>.pid`;
   - the projects root defaults to the repo's `projects/` unless the caller pointed it, and the audit hook does not watch the run script's subprocess.
   - **Reaches:** `~`, `$XDG_RUNTIME_DIR/molbuilder`, and potentially the repo's `projects/`.
5. **Runs the real env manager.** `tests/test_envs_install.py:977-1013`. `test_the_shim_runs_a_readonly_verb...` runs the real `bash scripts/install-env.sh list`, which uses the real conda and the real `molbuilder` host env's python (`python -m molbuilder envs list`). It is a read-only verb and `HOME` is temporary. **Reaches:** the real conda manager and the host env.
6. **Latent: the developer's env removed.** `tests/test_envs_install.py:1302-1346`. `test_clean_REFUSES...` binds the real host env prefix (`sys.prefix`) and runs `envs install molbuilder --clean --yes`.
   - Only fakes of `builds.dispatch_into_env` and `probe_env_state` stand between a refusal regression and removing the developer's env.
   - `diagnostics.detect` is not faked, although install re-detects after a removal step (`envs/install.py:1240`, `reset_capabilities()`).
   - **Reaches (latent):** the `molbuilder` conda env.
7. **Real sockets on localhost.**
   - `tests/test_monitor_notify_policy.py:498-502` POSTs for real to `http://127.0.0.1:9/nowhere`, a fixed port.
   - `tests/test_monitor_notify_policy.py:601-622` and `tests/test_notify_setup_api.py:260-282` POST to an ephemeral port that was bound and released; another process could take it in between.
   - **Reaches:** the localhost network.
8. **Helper exposure: the incident's mechanism.** These helpers write the machine record or config through `machine_scope_path()` / `machine_config_path()` with no refusal of a real root:
   - `tests/test_restart_files.py:34` calls `support.road.run_road_case` (`_road_target`, then `write_machine_record(**record)`; `_write_machine_config`);
   - `tests/test_a_sent_run_the_scheduler_forgot.py` calls `support.road.prepared_here` (`conftest.write_machine_record(env_init=...)`);
   - `tests/test_results_views.py:95` calls `write_machine_record()`.

   Under pytest they are safe because of the function-scoped autouse isolation. Called by hand, or from a module fixture, they write the developer's real `environment.json` / `molbuilder.json`.

## 3. Patterns

- **Isolation is per-test, but much code runs before any test.** `config_root_is_never_the_developers` is function-scoped. Code that runs at collection or in a module fixture meets the developer's real HOME, XDG and config dir:
  - `_road.conda_hook()` and `_road.env_available()` in e2e `skipif` and module globals;
  - `_BACKENDS = available_backends()` at import;
  - `support.live_server.serve()` in a module fixture.

  `outside_the_developers_folders` exists, but nothing forces a module fixture to call it, and `serve()` and `_live` cover only part of the environment.
- **Helpers write records with no guard of their own.** `write_machine_record`, `prepared_here`, `run_road_case` and `_write_machine_config` all resolve their target through `machine_scope_path()` / `machine_config_path()` at call time and trust the caller's isolation. That is exactly how the 2026-10-30 fabricated `environment.json` got written.
- **Faking the network is per-test opt-in.** Faking `urlopen` is opt-in per test, and one parametrize row (`test_no_verb_hands_out_a_secret[post…/test]`) forgot it, so each run POSTs to Slack. "A real refused connection" is produced with live localhost sockets.
- **"The road cannot reach this" became a licence to plant state.** Pre-seeded `environment.json` snapshots in calculations recur in prep_bench_fold, bench_grid_card, launch_door_gate and the reused `_prep` of test_engine_offset. Launch records are written for submissions that never happened. Scheduler, `nvidia-smi`, conda and mamba answers are typed. A fake PySCF `mol` feeds the emitter, and stand-in servers feed the JS tests. "Written by the product's own writer" was treated as making a planted state legitimate. A machine record in molbuilder's own format is allowed by tier 1; a calculation's snapshot is prep's product.
- **Shortcuts around the designed doors.** Four files fake the picker root by patching the `Capabilities` class instead of using `isolated_projects_root`: bench_grid_card, pdb_workflow_integration, reserved_label_one_store and restart_files. Describe goes through the library rather than the verb. Records are read with raw `json.loads` instead of their readers. Test modules import each other's private helpers as libraries.
- **Older releases' files are still built** for refusal tests (a pre-v7 sidecar, notify files from before 2.27.1, a spectra record "written before it"), against testing.md § 6.
- **Browser tests run in the basic tier** because they are named `_js.py` or plain (`test_form_schema_setvalues_js.py`, `test_pages_no_js_errors.py`), so the e2e marker and its skip never apply.
- **Stale self-descriptions:**
  - `test_http_status_contract` promises an endpoint-count check that does not exist;
  - `test_prep_refuses_before_writing` promises refusals it does not test;
  - `test_frame` and `test_path_framework_doors` cite sections that no longer exist;
  - `test_wrapper_notify_flags` describes a wrapper road it does not test.
