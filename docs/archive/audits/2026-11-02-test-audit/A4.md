### ROGUE findings (first)

  - Nothing in `write_machine_record` or `run_road_case` refuses a config root that is not a temp dir.

**R2. The same helper, three more writers into the real config dir.** All reached by `test_molbuilder_json.py`.

  - Reaches `~/.config/molbuilder/environments/sol.json`.

**R3. A third helper call.** `tests/test_prep_calculation.py:306` calls `support.road.prepared_here`, which calls `write_machine_record` at `road.py:235`.
- Same writer as R1, same real target `~/.config/molbuilder/environment.json` outside pytest.

**R4. A module-scoped fixture reads the real config.** `tests/test_dna_double_strand.py:100-104`, fixture `_x3dna`.
- The chain is `auto_backend_name()` → `available_backends()` → `_amber.is_available()` → `diagnostics.get_capabilities()` → `detect()` → `read_config()`.
- Because the fixture is module-scoped, it runs **before** `config_root_is_never_the_developers` for its first test (`:107`), with the shell's HOME, XDG and `MOLBUILDER_CONFIG_DIR`.
- So it reads the developer's real `~/.config/molbuilder/molbuilder.json` and runs the real `conda env list`. It only reads.
- A malformed real config would fail the fixture.

**R5. A module-scoped fixture runs pip with the real environment.** `tests/test_wheel_ships_the_front_end.py:32-56`, fixture `wheel`.
- It runs `pip wheel --no-deps --no-build-isolation -q` (`:50-53`) and `git ls-files` with the inherited environment, before any isolation and without `outside_the_developers_folders`.
- pip writes `~/.cache/pip` (its wheel cache and version self-check) and reads `~/.config/pip`.
- There is no `--disable-pip-version-check`, so pip's self-check can reach pypi.org over the **network**.
- Reaches: the user's home cache and the network.

**R6. The field test reaches the real scheduler by design.** `tests/field/test_the_queue_says_why.py`.
- `:27` calls `expanduser` on `MOLBUILDER_FIELD_RECORD`, normally `~/.config/molbuilder/environments/<name>.json`, and reads it.
- `:51-52` and `listed()` run the **real `squeue`**.
- The module fixture at `:77-86` reads the record without isolation.
- All of this is read-only and is the stated purpose of tier 2 (`testing.md` § 0). It is listed only for completeness.

**R7. Reaches that happen only if a guard regresses.**
- `tests/test_cli.py:557-565` runs `serve foreground --no-auth --host 0.0.0.0 --port 8099` with the **real** `create_app`. If the loopback refusal regressed, `app.run` would bind 0.0.0.0:8099 on the network and hang the test. The sibling `test_security_headers.py:152` stubs `create_app`; this test does not.
- `tests/test_admin_reload.py:301-307` runs the real `jupyter start --port 59999`. If the config-read refusal regressed, it would start a detached Jupyter server.

**R8. A low-severity helper write.** `tests/support/pages.py:52-66` (`every_served_page`).
- It calls `create_app` with every auth provider, which goes through `web/auth._install_secret_key` and creates `config_dir()/secrets/secret_key`.
- The create is exclusive, so it never replaces an existing key, but it does not refuse a real root.
- Reached by `test_security_headers.py:101` and `test_wheel_ships_the_front_end.py:113`. Inside pytest both are isolated.

**R9. Child processes the projects-tree guard cannot see.**
- `test_admin_reload.py:386` and `:430` start children (`python -c`, `serve foreground`) that inherit the sandboxed environment but run outside the conftest audit hook. A regression in such a child that touched `projects/` would not be caught.

## 3. How the handcrafting and the reach crept in

**1. The guard lives in pytest's lifecycle, not in the writer.**
- `config_root_is_never_the_developers` isolates only a function-scoped test.
- The writers it was meant to protect ask `config_dir()`, `machine_scope_path()` and `machine_config_path()` at call time and accept whatever root that resolves to. Those writers are:
  - `conftest.write_machine_record`
  - `road._write_machine_config`
  - `road._road_target`
  - `pages.every_served_page` (through `create_app`)
- So the shared road meant to be the one safe way in is exactly where a hand run, or a module fixture, writes into the real folders. The fix belongs in those four writers: refuse a root that is not under the temp base.

**2. Module-scoped fixtures silently run before isolation.** `wheel` and `_x3dna` each run product code or tools with the developer's real environment. Nothing flags it, because the canary only fingerprints the config tree, and neither fixture writes there.

**3. Handcrafted records come back as migration tests.** After the 2026-10-16 rule, tests of `jobset migrate`, sidecar schema gates and retired keys still rebuild older releases' files by hand: job-set, job-request, run-file names, environment.json and v2–v9 sidecars.

**4. Front-end tests type the server's reply to the shape the client expects.**
- The molview, chemistry, trajectory and notify stand-ins all do this.
- `test_molview_model.SERVER` records that one such stand-in already drifted from the real route.
- The cure is to make the reply through the Flask route once per shape.

**5. Front-end code that cannot be imported is lifted by text.** Some lifts are anchored on comments or indentation (`_slice`, `_fn`, the `rebuildModel` index), which makes a comment edit a test failure. `_node_esm.lifted` exists but is used by only one of these files.

**6. Older layers keep their shape-pins and direct renderer calls.**
- The 2026-06 era "pin the canonical shape" files (`test_shared`, `test_envs_recipes`, the trivial checks in `test_structure`, `watch/*`) are still present.
- Direct `spec_for` → `render_deck` tests predate the road rule.
- Neither has been swept.
