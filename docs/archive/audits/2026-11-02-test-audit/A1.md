### ROGUE findings — active (they reach outside the sandbox on an ordinary pytest run)

1. **`tests/test_envs_solve_drift.py:90-96`** (module-scoped fixture `solved`, with `:43-55`, `:65-70`):
   it runs the developer's real `mamba`/`conda` (`create --dry-run --json -n _molbuilder_drift_probe -c
   conda-forge --override-channels`) from a MODULE fixture. That fixture is built before the
   function-scoped autouse `config_root_is_never_the_developers` (conftest.py:507-583) applies, and it never
   calls `outside_the_developers_folders`. So it runs with the developer's real `HOME`/`XDG_*`: the real
   `~/.condarc`, the real package/repodata caches under the real conda root or `~/.conda`. It also goes out
   to the network (conda-forge). The `slow` mark does not keep it out of tier 1: `none2e` is
   `["tests/", "--ignore-glob=*_e2e.py"]` (tools/testrun.py:55).
2. **`tests/test_serve_log_is_private.py:26-27`**: `tempfile.mkdtemp()` in the system `/tmp`, outside
   `tmp_path`, never removed. Each run leaves four directories with 0600 logs.
3. **`tests/test_makov_payne.py:124, 138`**: `tempfile.TemporaryDirectory()` in the system `/tmp`, outside
   `tmp_path`. It cleans up after itself; this one is minor.
4. **`tests/test_envs_clean.py:41-60`**: three tests invoke `envs clean` with nothing patched.
   `cmd_clean` calls `get_capabilities()` before it checks the recipe (molbuilder/envs/_cli.py:732), and
   `detect()` then asks the REAL conda registry (`conda env list --json`, through conftest's delegating
   conda stub). Read-only. `tests/test_structure_save_endpoint.py:34` makes the same real read through
   `diagnostics.get_capabilities()`.
5. **`tests/field/test_ask_the_target.py:34, 58-67, 93-94`**, by design (tier 2, collected only with
   `MOLBUILDER_FIELD_RECORD`). `RECORD` is `expanduser`-ed at import, before the autouse fixture moves
   HOME, so `~` there is the real home and the record read is the user's real one. The gate passes the
   `--test-only` call to the REAL scheduler's submit command. Intended, and gated, but it is a reach.

### ROGUE findings — latent (outside pytest, from a module fixture, or if the guarded code regresses)

6. **`tests/test_gpu_contract.py:33`, `tests/test_the_catalogue.py:29`**: both run every row through
   `support.road.run_road_case`, which is exactly the incident chain:
   - `_road_target` (road.py:544-610) calls `write_machine_record` (conftest.py:1173-1212, on
     `machine_scope_path()`). Its default is the incident's record: preamble `"true"`, no `machine`, no
     `detected_at` (conftest.py:1198-1203).
   - `a_machine_with_queues` (road.py:354-356) calls it the same way.
   - road.py:603-609 writes `environments/sol.json`.
   - `_write_machine_config` (road.py:1133-1142) writes `molbuilder.json`.
   - The "unprobed" branch unlinks `machine_scope_path()` (road.py:593). Outside pytest that **deletes the
     real `environment.json`**.

   None of these refuses a real root. Under pytest they are isolated only by conftest's function autouse.
   The catalogue table's `machine = "workstation"` (the_catalogue.toml:18) reaches road.py:598. The GPU
   table's default reaches road.py:596. Its row "a prep for another machine reads that machine's record"
   (gpu_contract.toml:280-284) reaches road.py:603-609.
7. **`tests/field/test_ask_the_target.py:71-75`**: `write_environment(..., machine_scope_path())` directly.
   Called outside pytest, it replaces the real `~/.config/molbuilder/environment.json` with a record whose
   submit command is a gate script in a pytest tmp dir that is about to vanish. That is the incident's
   shape: real runs then fail.
8. **`tests/test_envs_clean.py:103-115, 143-156`**: `clean --yes` does `rm -rf` of `build/ src/ .ccache/
   .cache/ .tmp/`. Its target is redirected only by two name patches,
   `molbuilder.envs._cli.get_capabilities` and `molbuilder.envs.install._env_prefix` (_cli.py:732, 757).
   If the code stops resolving through exactly those names, the deletion lands in the real
   `molbuilder-siesta-gpu` env's `opt/siesta-gpu-stack/`. The env canary (conftest.py:337-389) watches only
   `conda-meta` and `site-packages`, so it would not see it.
9. **`tests/test_serve_verbs.py:261-274`**: `serve start --port 8123` patches `read_pid`/`pid_state` but
   NOT `daemonize`, which its sibling patches at :295-296. If the refusal regresses, a real detached
   server starts and outlives the test. `:306-331` (`serve status --port 9329`) makes a real HTTP request
   to localhost:9329.
10. **`tests/test_notify_listener.py:51-61`** `_seed_keys` writes `notify_keys_path()` (the config dir)
    with no root check. Every caller sets `MOLBUILDER_CONFIG_DIR` first, so it is safe under pytest.
11. **`tests/test_envs_install_plan_executes.py:98-145`**: if `activation_wrapper` stopped putting the
    prefix's `bin` first, the real `python -m playwright install chromium` would download over the network
    (contained in the tmp prefix).
12. **Traversal guards' own tests** (`test_structure_save_endpoint.py:101-104`,
    `test_web_files.py:682-698, 2920-2948`): a fence regression writes `../secret.xyz` relative to the
    working directory, or reads `/etc` through a symlink.

## 3. Patterns

The handcrafting came in through **shortcuts that were never moved back onto the road**, and through helpers
reused across files:

- `test_engine_offset_reaches_every_deck._prep` plants the calculation's `environment.json` snapshot and
  builds the description through `describe.build_description`. Two group files import that private helper
  (`test_electronic_state.py`, `test_validation_delivery_contract.py`), and `test_value_axes.py` copies the
  same pattern. One shortcut now spans every science-through-prep test.
- `test_prep_from_the_browser.py` predates `support.road.describe_calculation`. It still types `task.json`,
  `job-request.json` and a named machine record with the schema strings spelled by hand.

**Isolation is by convention, never by construction:**

- Every config write in the group relies on conftest's function-scoped autouse fixture.
- The shared writers (`conftest.write_machine_record`, `road._road_target`, `road._write_machine_config`,
  the field test's `machine_scope_path()` write) all write wherever `machine_scope_path()` or
  `machine_config_path()` answers, and none refuses a real root. That is the incident chain, and two group
  tables run it on every row.
- A module-scoped fixture (`test_envs_solve_drift`) escapes the autouse isolation outright.
- Destructive commands are aimed by `mock.patch` on names (`test_envs_clean`) rather than by a recorded
  fake manager.

**Smaller patterns:**

- Typed machine and manager answers persisted where § 0 now forbids them: conda's JSON, cgroup text.
- JS tests still lift or grep shipped source (`fetch-error.js`, `projects-sidebar.js`) instead of loading
  the module through `_node_esm`.
- Per-call-site test writing left duplicates and API-presence tests in older files: diagnostics,
  `spectra.json`, backends, knobs.
- Docstrings claim coverage that no longer exists: BOM tolerance, `kind` filtering, the "no other source"
  pin.
