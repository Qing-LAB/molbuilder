## 3. How the handcrafting got in

Six habits account for most of what I found:

1. **A precondition met by spelling the record instead of asking its door.** Prep refuses without a machine record, so some tests wrote one as a dict at a spelled path (`test_target_machine_choice`, `test_warm_file_inventory`) instead of using `write_machine_record` / `write_environment`. The record that came out has exactly the "no machine, no probe date" shape that broke the user's runs.
2. **Helpers that write config without refusing a real root.** Every config writer (`write_machine_record`, `_write_machine_config`, `run_road_case`, the `machines` fixture) trusts the caller's isolation. Under pytest's function scope that holds. Called any other way, nothing stops it, and that is how a road helper run by hand wrote the real `environment.json`.
3. **Contract examples copied into `tests/data`.** `task_example.json` and `job_request_example.json` are a document's examples, kept in line "by review". The tests then round-trip a record molbuilder never wrote.
4. **Fakes of outside answers, so a parser can be tested in tier 1.** A fake conda typing JSON, `fetch` stand-ins typing server rows, hand-typed wire blocks. Each was added so a reader could be tested without the real producer. testing.md § 0 now forbids exactly this.
5. **Calling the renderer or private emitter directly, with a hand-typed deck.** `script_emit`, `effective_parameters_record`, `warm_file_inventory`. The test then pins the block's spelling ("pins the block shape so a future format change is loud") instead of what prep writes.
6. **Older-release files rebuilt by hand to test migration refusals.** v3 sidecar, `task@1`, `flat`, `enabled`, a v3 deck block. This happened after the § 6 rule of 2026-10-16 said no test builds an older release's files.

The well-built files show the alternative: `test_structure_pair_one_generator`, `test_transport_task`, `test_launch_values` (apart from its helper) and `test_trajectory_log_stage_targets` make their inputs through writers, routes or `describe → prep`.
