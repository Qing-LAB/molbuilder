# E2 — end-to-end tests (22 files): rogue, handcrafted, and whether each earns its place

Read whole: `docs/process/testing.md`, `tests/conftest.py`, the 22 files, and the helpers they reach:
`tests/support/live_server.py`, `tests/support/real_runs.py`, `tests/_road.py`, `tests/support/road.py`
(the helpers used), `tests/support/task_setup_page.py`, `tests/support/machines.py`, `tests/support/findings.py`,
`tests/support/envelope.py`. I also checked the product code that module-scoped fixtures reach:
`molbuilder/web/app.py::create_app`, `diagnostics.detect/initialize`, `monitor.read_notify_keys`,
`projects.projects_root`, `describe.write_description`. I ran nothing.

## 1. Summary

**Verdicts by file (22):** keep **3**, fix isolation **19**, rewrite through the road **0**, retire **0**.
Within the files, by test: **6 to retire** (5 tests and 1 fixture), **4 to rewrite** (one of those is
a fake that needs your ruling).

**No test in E2 writes into your real config, state, or `projects/` folders.** Every write I traced (the
machine records, `environments/sol.json`, the notify channels file, the projects trees) lands in a pytest
temp directory. What E2 does have is **reads of your real `~/.config/molbuilder` that happen before any
isolation**, and **one latent write** that only the order of autouse fixtures keeps safe.

### ROGUE findings, worst first

1. **LATENT WRITE of a fabricated `environment.json` (it depends on the order autouse fixtures run in)**
   - **Where:** `tests/test_task_setup_prep_e2e.py:51-67`, the `this_machine_is_a_cluster` autouse fixture.
   - **What it writes:** it calls `write_machine_record(scheduler=SLURM, …, env_init={"preamble": "true", …})`
     at `machine_scope_path()`. That record has the same shape as the one that broke your machine.
   - **Why it is safe today:** pytest happens to run conftest's `config_root_is_never_the_developers` first.
     The fixture does not request it as a dependency, which `_this_machine_has_been_probed` in conftest
     does. If the order changes, or the scope is widened, it writes `~/.config/molbuilder/environment.json`.
   - **Same exposure outside pytest:** if these helpers are called outside pytest they write into
     `~/.config/molbuilder`. Nothing in them refuses a real root, and `conftest.write_machine_record` does
     not refuse one either.
     - `_two_stages` (`:1092-1095`, a machine record)
     - `a_named_machine` (`:1180-1190`, `environments/sol.json`)
     - `test_the_notify_card_offers_this_machines_channels` (`:1282-1287`, the notify channels file)
     - `test_pyscf_relaxation_outcome_e2e.py::_run` (`:65`, `:103-104`)

2. **Module-scoped live servers read your real config (read only).**
   - **Mechanism:** `support.live_server.serve()` → `create_app(config={})` → `diagnostics.initialize()`
     → `detect()` → `read_config()` reads `~/.config/molbuilder/molbuilder.json`, or your shell's
     `$MOLBUILDER_CONFIG_DIR` (only the function-scoped autouse clears it).
   - **Secrets too:** `create_app` also calls `monitor.read_notify_keys()`, which reads
     `~/.config/molbuilder/secrets/<notify keys>`. If that file is set up, your real signing keys are
     loaded into the test server and its notify route is registered.
   - **Also:** it runs `conda env list` and `nvidia-smi`.
   - **Why the isolation misses it:** a module fixture is built before the function-scoped
     `config_root_is_never_the_developers`. The fixture does not call `outside_the_developers_folders`.
   - **Effect:** a malformed real `molbuilder.json` errors the whole module.
   - **Files and lines:**

6. **HOME is real inside module-scoped engine roads.** `outside_the_developers_folders` sets
   `XDG_CONFIG_HOME` and `XDG_STATE_HOME`, but not `HOME` or `XDG_RUNTIME_DIR`.
   - **Who inherits it:** run scripts, `conda activate`, and the `molbuilder` CLI that `_at_a_terminal`
     starts (`real_runs.py:279-282`, with `cwd` = the repository root).
   - **Fixtures affected:** `test_sequence_of_groups_e2e.py:75-129`, `test_siesta_stopped_run_e2e.py:97-114`,
     and every `live_siesta` / `_road_at` road above.
   - **Exposure:** `config_dir`, `state_dir` and `jobs_dir` stay isolated because the XDG variables are
     set. Anything that uses `Path.home()` directly, or that the child process reads from `~` (conda's
     `~/.condarc`, `~/.conda`), is the developer's.
   - **Severity:** none observed writing; low.

7. **Background engine runs can outlive a failed fixture.** A failure between the background launch and
   the stop leaves a real SIESTA job running after the test, because neither place uses `try/finally`:
   - `test_sequence_of_groups_e2e.py:97-122`: the background `launch` is followed by reads and only then
     `jobs stop`.
   - `test_siesta_vibration_e2e.py:1521-1541`: `until(…, within=900)` before `_stopped_by_its_line`.

## 3. How these tests came to be designed this way

- **Module fixtures trusted the per-test isolation.** Each file's own `flask_server` fixture was written
  when "a server" meant "no state". Later, `create_app` started reading the machine config, the conda
  registry and the notify secrets at start-up (`diagnostics.initialize`, `read_notify_keys`), and nobody
  went back to the 14 module-scoped copies (13 `serve()` fixtures and `test_molview`'s own). The suite's isolation is per test by construction, and a
  module or session fixture is the one place it silently does not apply. `outside_the_developers_folders`
  exists, but nothing forces a module fixture to call it. The engine skip goes further: it is evaluated
  at import, before any fixture at all.
- **Helpers were copied instead of extended.**
  - `_register_tmp_as_picker_root` is pasted into 8 files (7 in E2, plus `test_chemistry_card_e2e.py`),
    with a dead `caps` and a class-level patch that bypasses the one door `isolated_projects_root`.
  - `_jobset`, `_set_item` and an inline `live_siesta` are re-written beside their originals.
  - `test_molview` re-wrote the live server and lost its projects tree.
- **Planted state crept in as shortcuts to a page's state.** It was rarely an engine output.
  - **Browser state:** `sessionStorage` slots, and `publishCommit` / `setShared` by `evaluate`.
  - **Folder state:** a `task.json` typed to trip a guard, a queue no record lists, route texts written to
    disk by the test, a workspace file deleted to stand in for 31 saves.
  - **Machine state:** fabricated SLURM/workstation records with `preamble "true"`, written per test.
- **The engine tests are the cleanest part of this group.** Runs are made on the road, once a session,
  copies altered through `copy_of`, and expectations come from the contract or an independent reading of
  the output. Their exposure is the reads of the real config, the real HOME, and background jobs with no
  `finally`.
