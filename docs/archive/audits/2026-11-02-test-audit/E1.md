## 3. How handcrafted inputs got in

1. **Isolation only covers function scope.** Every per-test protection works because of a function-scoped autouse
   fixture. The e2e files build their expensive pieces in module scope, or at import, and call product code with the
   developer's environment:
   - the server's start, through `create_app` → `detect` → `read_config` and `read_notify_keys`;
   - the skip checks (`conda_hook`, `env_available`);
   - `real_runs._engine_here`.

   Two shared doors would close almost all of it: `support/live_server.serve` and `_road.conda_hook` / `env_available`.
   `_live` / `outside_the_developers_folders` would also need to redirect HOME and `XDG_RUNTIME_DIR`, and clear
   `MB_NOTIFY_*`.
2. **Failures that are hard to make on demand were planted, then described in the road's words.** Examples:
   - a bundle member rewritten;
   - an mtime forged "as a kill mid-write leaves it";
   - a digest moved away;
   - today's deck cut down to look like an older release's.

   Each docstring says what a real run would do, but the input is made by hand.
3. **A second mechanism for a door that already exists.** Four files monkeypatch `Capabilities.file_picker_roots` or bind
   a fake `Capabilities` rather than point `MOLBUILDER_PROJECTS`. The bench test re-isolates HOME/XDG itself, loses
   conftest's machine record, and then writes the calculation's own `environment.json` to get past prep.
4. **"It is the same writer" reasoning.** Calculations are assembled from `write_task`, `template_with_values`,
   `job_request.write` or `describe.write_description` instead of `molbuilder describe`. That produces states describe
   never writes.
5. **Testing the listener instead of the producer.** Synthetic `CustomEvent`s and `page.route` stubs stand in for the
   component that broke. So the defect a test names in its docstring (the dispatcher's missing success signal) cannot
   turn it red.
6. **Prep-only API tests placed in engine files** because the file already had a `_describe` helper. They then run
   serially on the engine worker, with the engine's environment.
