## Confirmed W and C findings

**E-D1 (C).** Take a transport calculation whose composed junction pair does not read: the sidecar is damaged or edited by hand, or it was written by a molbuilder older than the codec accepts. Opening it on the Results tab gives an HTML 500 from both `/api/transport/record` and `/api/transport/pdos`, and `molbuilder jobset summarize task` ends in a Python traceback. Prep of the same folder says the reason in words. **Smallest fix:** in `collect_record` and `selection_pdos`, catch `ComposeError` around `recorded_junction` and raise `RecordError` with its words. Every route and `summarize task` already turn a `RecordError` into a refusal.

**E-D2 (C).** Take a point whose deck's `molbuilder shared` block no longer reads (its fences broken by a hand edit). The Results tab's report for the whole calculation is refused with a 400 that names no deck, and `summarize task` prints a traceback. **Smallest fix:** move `sharing_of(where)` inside the per-point guard, or catch `DeckRecordUnreadable` there. That point then goes to `failed` with the reason, naming its deck, and every other point still reads.

**F-D1 (W).** Take a SIESTA vibration whose finish failed. The person follows § 5.5 and runs `mb_vibration.pyz finish` by hand. The spectrum it writes says the relaxation was "not requested" (`enabled` false) although the run's `relax` call ran, and says Raman was "not requested" although it was asked. Above the force tolerance, the session log and the file tell the person to untick `already_relaxed`, which is already unticked; the right remedy is more `relax_steps`. **Smallest fix:** let `_finished` find the call's run as the `record` step does. Then pass the `relax` call's record from the run's index to `result_of`, and apply `_with_raman_phase`.

**F-D2 (W).** Take a PySCF vibration of a structure stated already relaxed that carries its own `info.calculation`. A frame set written from its modes gets no `info.calculation`, so it cannot serve as a transport citation. The person is told "a PySCF deck states none" instead of getting the structure's own record, as § 5.10 ③ says. **Smallest fix:** decide "stated relaxed" from the result's `relaxation.already_relaxed` (both engines write it), or from the description, not from the SIESTA deck's block.

**G-D1 (W).** Take a structure saved from a finished run whose deck stated a charge (or spin). The person presses Apply on the Cell page without changing anything. The structure comes back marked `structure_modified`, and the page warns about "a cell that is no longer there". A later calculation with `net_charge` blank then ignores the recorded charge and falls to the phosphate rule (0), so the deck carries the wrong electron count unless the person notices the resolved source. **Smallest fix:** in `apply_edit`, set the mark only when the edited box differs from the incoming one (compare the two periodicity blocks); or keep Apply disabled until a field is changed.

**G-D2 (W).** Labelled species are allowed input (`chemistry.md` § 3), for example `H1`, a hydrogen with its own basis. A hydrogen labelled `H1` is taken as a heavy atom with the 1.95 Å cutoff. An `H1` hydrogen-bonded to a bare phosphate oxygen makes that oxygen look bridging, so the charge step for a blank `net_charge` gives 0 instead of −1 (reproduced). A labelled oxygen also gets the default electronegativity, so the polar-molecule advice can stay silent. **Smallest fix:** use `is_atom(e, "H")` in `_adjacency` and `estimate_partial_charges`, and look up the electronegativity by `resolve_element(label)`.

**P-D1 (W).** A person opens a SIESTA `.out` that molbuilder did not write, from a deck with no `AtomicCoordinatesFormat` (SIESTA's default is Bohr) or with `AtomCoorFormatOut` set to Bohr or Fractional. They open it from the Results picker, `watch parse` or `postprocess.parse`. Every frame comes out 1.89× too large, or fractions are read as Å, and species labels become elements. **Smallest fix:** read the unit from the `outcoor:` heading (`(Ang)`, `(Bohr)`, `(scaled)`, `(fractional)`) and convert. Failing that, flag the frames as not understood, per parse rule 9.

**P-D2 (W).** A person runs an open-shell (unrestricted) PySCF relaxation and opens its `<stem>_geom_optim.xyz`. Each frame's SCF chart shows the previous evaluation's SCF; frame 0 shows the stability SCF. The final energies do not match the frames', yet the run info says every frame was upgraded. The default `.molwatch.log` view is not affected. **Smallest fix:** pair each frame with the SCF run whose converged energy matches the frame's comment energy. Or drop the SCF runs logged before the optimization starts: the deck already prints its stage banners, and one could serve as the marker.

**P-D3 (C).** Once one validly signed report carries a non-number `sent_at`, `GET /api/notify/reports` answers an HTML 500. The This machine tab then lists no reports until that log rotates away. **Smallest fix:** in `read_reports`, count a line whose `sent_at` is not a number as skipped. Or have the listener's `_clean` keep `sent_at` only when it is a number.
